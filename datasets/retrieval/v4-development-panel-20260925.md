# V4 开发与终验事实分组（2026-09-25）

本轮解决原 20 道开发题全来自 Docling、缺少跨文档和无答案场景的问题。最初考虑新增各来源题目，但检查发现只是把旧测试题换一种问法，仍会把同一事实标签带进开发集，因此废弃该草案；没有用它运行模型或计算质量结果。

最终方案从现有冻结原文中另选此前未标注的事实，形成 24 道公开开发题和 12 道宿主终验题。开发题为 direct / semantic / cross_document / unanswerable 各 6 道，终验各 3 道。两者均涉及六个来源，各自的可回答题围绕六个事实簇展开。单事实的精确问法、中文转述和含该事实的组合题留在同一 split。

原 60 题文件完全保留，明确标为“已见历史回归”，不再将它描述为新的独立终验。新 dev / final 之间以及它们与旧 60 题之间，题目 ID、完整问题文本、标注原文片段均无交集。片段不交集是可自动检查的保守条件；事实语义另外人工核读。开发和终验共享原始公开语料，属于新问题、不同事实簇的检验，不是跨语料泛化测评。

| 开发事实簇（每行同一原文证据） | 终验事实簇（不同片段） |
| --- | --- |
| Docling 未来新增识别模型计划 | DocLayNet 学习曲线的数据饱和现象 |
| ReAct 少量示例微调与模型规模比较 | WebShop 指标定义与测试规模 |
| Pi 分支摘要共同祖先及收集范围 | Pi 模型专用 token 配置校验 |
| Codex usage_count / 时间选择优先级 | Codex 空输入选择时的文件清理 |
| OpenClaw 明确配置 provider 故障行为 | OpenClaw 会话可见性和 DM 范围区别 |
| Hermes 重新整理摘要失败保留旧摘要 | Hermes 数据库同步避免恢复重复加载 |

逐题标注保存在 datasets/retrieval/retrieval_feedback_dev_v4.json 和 retrieval_feedback_final_v4.json：每条 gold 附事实组、精确原文引句、URL、页码、原始来源 SHA-256。无答案题附范围说明，询问语料未提供的具体测量，不使用历史题的私有账号/未来事件模板。标签为一次人工核读，尚未声称双人标注一致性。

校验器 research_agent/experiment_dataset.py 会核验事实组、原文引用、split、重复题、标注片段隔离、跨文档题来源数和数据哈希。初稿版本 20260925-fact-groups 纳入原文及标注元数据，修改问题或依据都会改变指纹。旧套件读取原文件的行为不受此模块影响。

本次阅读依据来自仓库已经冻结的原始材料，而非重新下载网页：Docling 技术报告（https://arxiv.org/abs/2408.09869）、ReAct 论文（https://arxiv.org/abs/2210.03629）、Pi compaction.md、Codex memories/README.md、OpenClaw memory-search.md、Hermes micro_compaction.py。每条准确 URL 和引用保存在对应 JSON，不把网页现在的内容冒充冻结版本。实现采取事实分组隔离与类别分层，不引入新框架、数据库或模型调用。

验证：tests/test_feedback_dev_panel.py 的初稿三项离线测试通过，包括错误原文、重复问题和跨组泄漏拒绝。它证明数据合同的边界，不证明检索性能；新的量化指标待受控检索执行产生。

## 冻结前标注复查

在任何新题排序或模型结果产生之前，再核读全部 12 个事实簇及其相关片段，发现并处理三处题意歧义：ReAct 微调数据来自正确答案轨迹，不把它称为人工标注；OpenClaw 的明确 provider 失败规则存在 none/auto/local 例外，问题现在指明 openai/ollama/gemini；Hermes 的“同步防恢复重复”在 :5 和 :11 也有宽泛表述，因此两道题改为询问只有 :10 明示的“旧行 active=1 导致摘要和原消息重复加载”。共调整 7 个问题文本，gold ID 未变，没有利用排名或模型结果选择标签。

所有 36 个 gold 引用经原文支持检查。审查中的其他相关片段不完整回答最终问题：例如 ReAct :23 给 WebShop 的 Score/SR 数字，而 :21 才给两指标定义；Codex :2 讲一般清理，:3 才明确空输入时占位文件和留待代理处理的合并产物。逐组相关片段及排除理由见同名 JSON 的 review。

复查确认早期 loader 没有实际检查 source_sha256，现已补齐。source_sha256 与冻结来源快照中记录的原始文件哈希比对；page 与原片段核对；新增 chunk_sha256 每次从精确原文重算；完整 corpus JSON 字节另写入合同指纹。这不等于每次重新下载网页或重读原 PDF 校验，边界已记录。

最终版本为 **20260925-fact-groups-r2**，数据指纹 **3b73d6c07a5d59b8104fcf57f49b9b5f5f66d78b04d485a29c099f3853375666**。四项离线测试通过，含来源哈希、片段哈希、页码篡改拒绝。两面板可冻结供随后评测；仍是同一作者的二次原文复核，不宣称独立双人标注。
