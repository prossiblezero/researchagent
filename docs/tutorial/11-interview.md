## 90 秒项目介绍

“ResearchAgent 是面向论文和技术研究的本地工作台，解决的是查资料之后难以追溯原文、长任务难以继续、提出方案之后难以验证的问题。

“架构上，我用 Python 显式组织 Agent Loop，工作台负责会话、意图路由和 SQLite 后台任务。普通研究通过搜索或本地混合检索找候选，再读原文，形成 Source–Evidence–Claim 关联并核验回答；会话、记忆和检查点让任务可以连续进行。

“用户要求自动研究时，上层控制器可以委派两个独立研究子任务，保存方案后调用 Codex 实现，再由宿主执行和测量，把指标与失败送回主控。我的重点是这套工具合同、证据、预算和恢复机制。

“评测上，我把检索和完整回答分开。在 SciFact 的 5,183 篇摘要、20 道可评分保留题上，混合检索 R@5 从 75% 到 87.5%。同时保留负结果：双路研究在当前对照总体没有提速，A-MEM 开发收益也没有通过独立留出验证。这些限制能从报告和轨迹追溯。”

## 三条值得准备到源码级的深挖路线

### A. 可信 RAG：从“有链接”走到“有原文支撑”

**问题：**检索命中不代表答案读过正文，真实链接也可能错引。

**实现：**SQLite 保存原始块与定位；BM25 + BGE-M3 + RRF 召回；`read_evidence` 读取原文与邻接块；Source/Evidence/Claim 分层；引用身份检查加段落语义核验；有界补查和局部修订。

**验证：**展示一条答案到 E 再到页码的链，引用 SciFact 限定检索成绩，同时说明完整问答是另一指标。

**取舍：**混合召回增加权重、索引和延迟成本；模型核验仍会误判，PDF 解析有盲区。检索权重与 chunk 策略需要对照测试。

追到：[retrieval.py](../../research_agent/retrieval.py) `retrieve/read` → [loop.py](../../research_agent/loop.py) → [verify.py](../../research_agent/verify.py) `check_answer`。

### B. 持久执行：从“重新跑”走到“知道怎么继续”

**问题：**服务中断后，重跑会重复工具和费用；旧请求迟到还可能污染恢复后的状态。

**实现：**SQLite Job 队列和执行检查点；状态包含工具对、证据、预算、草稿和核验进度；恢复检查记忆版本，增加 execution generation；关键回调核对代次；委派用调用 ID 做幂等。

**验证：**展示保存响应后不再次付费调用、未知在途响应不自动重放的测试。

**取舍：**只有已提交状态能可靠复用；外部 API 不保证 exactly-once；资料下载、代码和实验需要各自收据规则。

追到：[sessions.py](../../research_agent/sessions.py) `save_state/resume` → [workbench_store.py](../../research_agent/workbench_store.py) `claim_next/finish`。

### C. 自动实验：从“Agent 说成功”走到“宿主有测量”

**问题：**编码 Agent 自报的分数不能直接证明实验完成，更不能证明科研收益。

**实现：**版本化研究方案、结构化命令角色、冻结评分与输入、宿主执行收据、独立模型调用桥接、可比条件校验、基线/候选/消融和结果反馈。

**验证：**展示 A-MEM 三组预测与独立复算，以及独立留出未达到预定条件时主控如何交付负结果。

**取舍：**当前仍依赖本机环境，baseline 科学正确性需要审查；人工修正和恢复历史不能包装成全程无人干预。

追到：[auto_research.py](../../research_agent/auto_research.py) `assess_results/comparable` → [coding_tool.py](../../research_agent/coding_tool.py) → [locomo_metrics.py](../../research_agent/locomo_metrics.py)。

## 一个适合讲的真实失败：正确测量不代表正确方法

**情境：**A-MEM 开发中需要实现 MMR 候选，脚本可以运行，输出也能独立复算。

**问题：**源码审查发现冗余惩罚只比较第一条已选记忆，而方案要求对所有已选记忆取最大相似度。主控没有自行发现偏差。

**处理：**用可手算反例核对实现，修正为对应的最大值逻辑，在相同冻结记忆上重新测量，保留原错误运行和人工介入记录。

**结果与认识：**正确版本在开发集有部分指标收益，但 R5/EM 存在退化；独立留出 R@10 与 F1 都没有通过冻结收益条件。代码运行、结果可复算、算法与论文一致、研究收益稳定，是四层不同验收。

证据：[方法核对](../../evals/reports/amem-fixed-memory-method-audit-20261002/report.md) → [修正后测量](../../evals/reports/amem-corrected-measurement-audit-20261002/report.md) → [独立留出](../../evals/reports/amem-holdout-final-audit-20261003/report.md)。

## 五分钟演示顺序

1. **一分钟：**运行第 01 章 CLI 离线问答，展示真实生成的 Trace，说明它是 fixture 演示。
2. **一分钟：**打开隔离工作台，展示研究区、两个独立会话及后台任务状态。
3. **一分钟：**从已有真实案例的一句结论追到 E 引用和原文定位，说明它属于历史实测，和刚才 fixture 不混用。
4. **一分钟：**打开已有 Auto Research 报告，展示方案、代码任务、宿主 measurement、assessment 的关联。
5. **一分钟：**打开独立留出或并行报告，解释一个负结果、适用边界和后续验证思路。

真实产物入口：[演示文档](../auto-research-demo.md)。它包含历史本机地址与档案链接；现场优先准备可打开的文件，旧端口是否仍运行要以当时环境为准。面试无需临时发起长时间付费实验。

## 如果被问下一步，怎样回答才具体？

选择一个已有失败来设计下一步，不继续堆功能。例如：

- **约束转交：**冻结父问题中的否定约束，在子任务合同中显式检查完整传递，复用并行任务面板比较遗漏率与成本。
- **核验可靠性：**针对原文支持判断整理独立标注样本，比较误拒和误放，验证不同核验模型是否值得额外成本。
- **性能：**拆分父决策、子研究、模型网络、共享检索锁和汇合耗时，增加固定条件配对，再判断并行是否适合默认启用。
- **科研有效性：**先固定 baseline 算法与评分，独立切分、预注册指标和消融，再评估候选，负结果也按约定停止。

这些是建议的后续方向，不是本项目已完成的新成果。

## 常用术语速查

| 术语 | 在这个项目里怎么解释 |
| --- | --- |
| Harness | 模型周围的工具、状态、上下文、权限、预算和评测运行机制 |
| Grounding | 让答案事实落到实际来源与原文证据 |
| Provenance | 证据来自哪个资料/块/页码/版本 |
| Checkpoint | 可供继续执行的已保存状态 |
| Idempotency | 重复提交同一动作身份不会新建重复委派 |
| Ablation | 控制其他条件，去掉/替换一个机制观察变化 |
| Held-out | 预留且不用于本轮调参的数据；具体独立性看切分协议 |
| Measurement | 宿主收集并按合同校验的测量记录，科学有效性另需验证 |
