# 06｜记忆与上下文：保存全部，不等于每次发送全部

> 历史是档案，记忆是可选择的知识，context 是本轮实际输入。

[上一章](05-retrieval.md) · [课程首页](README.md) · [下一章](07-recovery.md)

## 问题：长会话既会超预算，也会混入不该使用的信息

把所有历史不断追加到 prompt，成本会上升，重要约束可能埋在中间。把历史全部摘要化，又可能丢掉精确数字和引用。跨会话直接共享摘要，还可能把另一个研究目标带进来。

项目用三个层次分别处理“保存”“选择”和“输入”。

| 层次 | 保存什么 | 主要位置 |
| --- | --- | --- |
| 原始档案 | 消息、资料、证据、任务事件 | SQLite 与原始文件 |
| 可复用记忆 | 偏好、发现、决定及来源、状态、作用域 | `memory_items` |
| 当前输入 | 当前问题、可见历史/记忆、工具对、压缩状态 | `Sessions.prompt_context` + `context.py` |

## 会话独立与历史分支

同一研究区共享资料、Notes 和设置，新会话拥有独立聊天历史。显式历史分支才继承选定边界之前的消息。

```text
会话 A：轮次 1 → 轮次 2 → 轮次 3
                    |
                    └─ 从已完成回答分支 → 会话 B：继承到轮次 2

同区新建会话 C：空聊天历史，仍可使用该区共享资料
```

源码 [sessions.py](../../research_agent/sessions.py) 中：

- `history_for_turn()` 按 `turn_seq` 构造历史，避免后提交消息进入当前运行。
- `fork()` 从用户问题分支时，把该问题作为可编辑草稿，历史截止到前一轮；从助手回答分支时继承到选定回答。
- `source_message_id` 等关联帮助追溯分支来源，原分支的未来消息不会自动进入新分支。

按需检索历史可以跨会话，但这是明确的检索结果，并带来源；不等于把所有会话合成一个聊天历史。

## 记忆的作用域、来源和状态

| 作用域 | 典型用途 | 限制 |
| --- | --- | --- |
| `session` | 本次会话的偏好、发现或决定 | 检查来源消息是否在可见历史内 |
| `workspace` | 当前研究区共享知识或偏好 | 限于相应研究区语义 |
| `global` | 用户明确的跨区偏好 | 当前合同仅允许偏好成为 global |

在 [memory.py](../../research_agent/memory.py) 里先读 `add()`、`visible()`、`snapshot()`，再读 `extract()`。

自动提取的 finding 必须保留可回查来源和原文摘录，先成为候选，再经证据支持检查升级；用户确认与 `evidence_checked` 的状态也应区分。任意历史回答不应直接成为已确认事实。

忘记操作还会记录 tombstone，阻止同一内容/来源被再次自动提取；相关记忆或历史变更使旧检查点失效。这里的“忘记”控制后续使用，不等于物理擦除全部原始历史，显式历史回查仍需按产品语义理解。

## 两层上下文管理

### 结构化裁剪：`build_context()`

每次模型请求前构造预算内输入：保护原始问题、必要控制信息、来源/证据映射、近期完整工具调用对；压缩较旧观察和正文摘录。受保护部分也放不下时明确失败，避免静默截掉关键约束。

输入上限还要减去输出预留和安全余量。当前 `_size()` 根据序列化 UTF-8 字节数除以 3 估算 token，因此它是预算启发式，不是供应商 tokenizer 的精确计数。

### 语义压缩：`ContextCheckpoint.project()`

接近输入预算约 80% 且有足够完整工具往返时，尝试把较旧进展压缩为结构化状态，保留近期工具对。摘要字段包括：

```text
goal / constraints / completed / pending
findings（绑定 evidence_ids）/ conflicts / searched / next_steps
```

原始用户要求和会话上下文锚点另行保护；摘要不得把待验证假设改成事实。失败的摘要不能覆盖已有有效检查点，无明显缩减收益也不接受新摘要。

因此，压缩后继续读取原文是系统正常行为。摘要帮助恢复任务方向，原文用于恢复精确细节。

## 为什么必须保护工具调用对？

`assistant.tool_calls[id=call_1]` 与 `tool.tool_call_id=call_1` 是协议上的一对。只保留结果或只保留调用，下一次模型请求可能协议错误，也丢失“这段结果回答哪个动作”的语义。

本项目按完整工具对裁剪，并在摘要中留下证据身份。长文本外部化时保留恢复指针，不能只留下“论文说方法很好”的无来源总结。

## 面试表达与自测

“我把原始历史、可复用记忆和当前输入分层。会话独立，资料在研究区共享；分支按轮次继承。记忆带来源和作用域，变更会使旧执行上下文失效。上下文采用结构化裁剪加有界语义压缩，同时保留工具对和原文指针，精确事实可回读。”

自测：压缩摘要与执行检查点相同吗？全局记忆为什么只开放偏好？忘记一条记忆是否等于删除所有原文？A-MEM 实验是否就是这里的生产 `Memory` 实现？最后一题答案见第 10 章。
