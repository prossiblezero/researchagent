## 问题：为什么项目里有很多不同的“通过率”？

单元测试检查程序合同，检索评测检查原文是否进入候选，完整问答检查最终交付，自动实验检查研究方法。它们回答的是不同问题，不能加总成一个泛化的“系统准确率”。

## 指标怎样读？

| 指标 | 含义 | 常见误读 |
| --- | --- | --- |
| Recall@k | 找到的 gold 相关项占该题 gold 相关项的比例，再按报告规则汇总 | 当成回答正确的题目比例 |
| MRR@k | 第一条相关项排名倒数的均值，top-k 外按 0 | 当成所有证据的完整覆盖率 |
| Answer F1 / EM | 按具体 scorer 计算答案词项重合或精确匹配 | 当成所有语义均正确 |
| 引用 ID 有效率 | 引用的身份是否存在于本次来源/证据集合 | 当成原文必然支持答案 |
| 任务通过率 | 同时满足冻结任务要求和评分规则的运行比例 | 与 HTTP 成功率或 Job 完成率混为一谈 |
| 用量覆盖率 | 有返回用量的请求占全部请求的比例 | 把缺失 token 当成零 |

召回应明确按文档、父块、证据还是历史会话计分。无 gold、证据映射不全的题可能不能计召回，需要报告排除数量，不能悄悄换分母。

### pass@k 与 pass^k

假设一题运行 n 次，其中 c 次通过，从中选 k 次：

```text
pass@k = 1 - C(n-c, k) / C(n, k)    至少一次成功
pass^k = C(c, k) / C(n, k)          选中的全部成功
```

实现见 `evals/agent_metrics.py`。例如三次运行两次通过，pass@2=1，pass^2=1/3。前者反映多次尝试的机会，后者反映重复可靠性；少量重复和相关问题不能支撑强统计结论。

## 320 条面板到底是什么？

构成为 QASPER 80、SciFact 60、HotpotQA 50、LongMemEval 50、项目场景 80。具体执行分为 **296 条检索任务 + 24 项工程回归**，另选冻结的 32 题做两臂共 64 次完整问答。

因此不能说“完成 320 次真实 LLM 完整问答并达到某准确率”。A-MEM 与并行专项另外报告，不累计到 320 中。

## 两个负结果，比只讲正分更能说明理解

**检索改善，完整问答仍可能下降。** 09-29 产品评测中，DeepSeek 完整问答从 9/32 到 7/32；协议适配和引用绑定成为阻塞。它说明优化上游召回不自动解决下游阅读、核验和交付问题。

**开发有效，留出可能无效。** A-MEM 独立留出三组各 40 题、同 1292 轮记忆：

| 组别 | Answer F1 | Evidence R@10 |
| --- | ---: | ---: |
| baseline | 33.68% | 42.00% |
| MMR candidate | 32.54% | 41.88% |
| Top10 control | 37.10% | 42.75% |

MMR 未达到事前冻结的收益条件。开发测量和最终留出不能拼成“全面提升”。这还是单 seed、少量对话子集，不能推出统计显著性。

**生产 Memory 与 A-MEM 要分开。** `memory.py` 是工作台中的来源记忆与作用域管理；A-MEM/LoCoMo 是通过自动研究执行器承载的实验案例。该案例的分数不能直接归因为生产记忆模块或主控研究策略的因果收益。

## 反馈如何变成可治理的策略？

在 [strategies.py](../../research_agent/strategies.py) 按以下顺序读：

```text
feedback → propose → 固定条件配对 evaluate
                         ↓
                     activate / 保留候选
                         ↓
                     pin 到任务 → finish → rollback
```

候选来自有限预设，例如查询规划、覆盖重排、阅读引导；它不更新模型权重。`evaluate()` 要求固定数据、来源、模型、预算和 scorer 条件，比较成功、引用、延迟和 token；缺少用量不能通过成本门槛。启用还核对当前活动基线，防止拿旧对照推广到新条件。

因此“反馈驱动策略改进”可以成立，“已经做了 Agent 强化学习训练”不成立。

## 动手：给一个数字做五项身份检查

从上表挑一项，回答：数据是哪份、分母是什么、baseline 是什么、冻结了哪些条件、失败保存在哪里。再选一个相同日期的原始回答或预测，沿报告链接追溯。

离线总入口是 `python -B evals/run_all.py`，它会运行全量测试及离线评测，并写评测产物；学习时先执行各章小范围练习即可。真实 runner 会调用模型、搜索或执行实验，应在计划复现时使用新输出目录并按该报告说明准备条件。

完成标准：能用“数据范围 + 对照 + 指标 + 结果 + 限制”五部分说完整一句话，而不只背百分比。
