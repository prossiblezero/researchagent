# 可验证的 Harness 策略改进

本次在已完成的 V3 及全部既有功能上增量增加跨任务反馈、有限策略候选、同条件重放、启用门槛、运行归因和回退。SQLite 保存状态，现有 BGE-M3 / FTS 检索与原文核验继续作为基础。本策略模块不训练模型、不执行生成代码；受控编码实验另见 docs/v4-controlled-experiments.md。

## 使用

木屋侧栏「策略改进与反馈」中选择本区一个研究任务，记录遗漏资料、漏读原文、无依据结论、成本问题或正向反馈。遗漏资料、漏读、无依据结论及新增“原文证据选择不足”可生成有限开关组成的不可变候选；点赞、复制或一般失败不直接等于正确答案，也不会自动修改策略。保留反馈来源、诊断及父版本。反馈可能判断错误，候选须经过重放。

查询规划通过当前所选模型生成最多两条互补查询，原查询始终保留。该调用有独立 purpose 和计量，失败时回到原查询。覆盖重排交错查询路径并优先不同原始段落；这是简单确定性排序，不是训练过的交叉编码器。阅读提示明确各子问题的原文覆盖要求，现有引用与答案核验不放宽。所有策略继续遵守原会话范围、来源授权、原文哈希及工具预算；记忆和历史查询不应用论文查询规划。

固定公开控制集的重放入口为 `evals/run_harness_strategies.py`。以独立输出目录运行 `--stage dev`、`--stage control`、`--stage live --model sudocode-luna`；`--stage report` 可从已存结果重新生成可阅读报告。默认脚本只访问冻结的公开来源，数据库与原文轨迹均放在输出目录。脚本拒绝覆盖已有试验。评测不从网页接受用户填入的“通过率”；可信本地评测程序调用 `Strategies.evaluate` 保存逐题配对与完整条件指纹。

通过门槛后，面板允许启用该版本；未通过者保留失败。启用只适用于经过同模型验证的任务，未验证模型回到原基线。每次研究开始固定版本及配置哈希；恢复同一任务仍用原快照，尝试次数按执行代次分别保留。新版启用后，最近五次同模型任务至少失败三次且成功率比批准基线下降超过 20 个百分点时，自动回退到父版本；这属于运行保护，不证明失败有因果关系。用户也可以手动回退。运行中的任务不被切换策略。

## 2026-09-27 普通问答原文重排

evidence_miss 候选复用原文阅读提示，并启用 evidence_rerank。保留旧三字段配置及哈希；新字段缺省关闭。仅 current documents 使用：召回后按授权读取最多40个完整父片段、至多80000字符，模型返回明确原文span。片段重排不等于答案模型已经读过，答案仍必须通过read_evidence打开引用来源。跨研究区/历史/记忆保持原有路径。

每任务至多2个新原文重排调用，原始用户问题、策略/源码/全文共同构成缓存键。付费请求前先预留，完整结果写conversation_events的harness_retrieval收据；恢复复用结果，未知在途调用不重发。取消时保留已返回收据，不发布结果，也不更新其他执行代次。模型调用失败回到原排序并明确降级；有效空证据不补无关片段，提示有限补查或说明证据缺口。这里的空结果只覆盖候选池，不能证明整篇文档没有相关内容。

引用核验支持显式全角引用归一和唯一内部段落ID误抄恢复；列表、表格及闭合代码块的紧邻纯引用按对应块绑定，代码内空行不拆块。代码中的字面表格、错源、后续新事实和未闭合代码不能借引。规则版本变更使旧段落缓存及checked_draft失效；模型仍须检查事实和所问覆盖。

通过语义核验的纯证据不足答复可以正常结束（evidence_insufficient），无需编造引用；事实断言、错引用和核验不可用仍不能通过。此项是基线和候选共用的交付语义，不归因于重排收益。

真实全链入口evals/run_evidence_qa_acceptance.py；新来源面板复用evals/run_independent_evidence_qa.py。每题两臂使用独立数据库，固定Luna、8工具/12轮/16k回答上下文，额外重排消耗单列。evals/postprocess_evidence_qa.py从实际回答请求窗口计算阅读覆盖，不能用EvidenceCatalog保存的全文推断全部读完。当前结果及首轮失败见[本轮报告](../evals/reports/evidence-qa-20260927/report.md)。

## API

均在 `/api/spaces/{space_id}/strategies` 下：GET 返回当前版本、候选、反馈、评测、尝试和切换历史；POST `/feedback` 接收 job_id/kind/note；POST `/propose` 接收 feedback_id；POST `/activate` 接收 version_id/evaluation_id；POST `/rollback` 接收 reason。无远程任意代码执行或客户端提交分数接口。

任务 Trace 的 run_started 记录策略快照；retrieve 的 tool_result 包含查询变体、策略哈希、触发原因、规划错误及延迟；conversation_events 的 harness_action 同步记录实际动作。harness_runs 归因到任务与模型，harness_attempts 保留恢复后的多次执行结果。模型请求计量包含规划调用；缺失 token 保持未知，不按免费请求统计。

## 评测解释

预注册见 [评测约定](harness-strategy-evaluation.md)。完整排名 Recall@5/10、MRR 与实际片段送达率分别报告。真实 Agent 另报答案事实项、引用安全、原文覆盖、任务成功、工具数、模型请求、token 覆盖和延迟。少量自编任务不能替代公开基准或外部生产性能。

历史 V2/V3 指标保留原始口径；不把检索提升直接写成回答准确率提升，不把本项目任务路由称为部门路由，不用八道题宣称千题规模。默认旧基线继续可用，候选未满足门槛时不会为了展示提升而启用。

## 最终复验（2026-09-22）

固定8题的两组Luna运行已完成，最终原基线5/8、查询规划候选6/8；平均耗时152.9→131.4秒。基线有一次核验超时且缺少计量，不能据此声称纯检索带来的成功率提升或完整成本降低。候选未通过成本门槛，默认仍为原基线。列表段引用绑定仍有失败，全部答案、原文与逐题复核见 [最终报告](../evals/reports/harness-strategies-20260921/report.md)。原始首轮与最终轮分别保留，没有以重跑成功覆盖失败。
