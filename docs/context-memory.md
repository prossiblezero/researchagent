## 2026-09-29 原文窗口与核验约定

read_evidence 默认1800字符，可显式请求1–12000字符；邻居各最多1800字符。返回连续原文、start_offset、end_offset、next_offset和total_chars。模型工作上下文需要截短时保留连续前缀，并同步end/next_offset到实际可见范围，下一次从该位置续读；保存的完整证据与哈希不变。

核验输入先保留完整正文，再按总体预算缩减并标记excerpted；不能把核验器收到全文视为研究模型通读全文。局部修订保留已核验段落和12000字符总长度上限，仅窄范围修正解码器定位的非法JSON反斜线。失败仍保留待核验稿，不升级为事实记忆。

2026-09-30 补充：预算不足时按引用该证据的各段结论选择核验窗口，每次从完整原文重新选择，避免连续截短永久丢失关键事实；引用绑定、来源角色和页码规则保持有效。核验重试共享时间预算，允许使用已配置的较长请求时限，仍服从父任务截止时间。

最近完整后端433/433、前端33/33（2026-09-30）；工程回归不代表研究成功率。最新[Luna reading-r3](../evals/reports/auto-research-foundation-20260929/scifact-reading-luna-r3/metrics.json)原文简报经局部修订后11/11段落通过模型核验；随后完整迭代任务的子调研仍核验失败，稳定性待改善。旧恢复runner仅验证ResearchAgent核验/修订，不代表完整Workbench或父研究恢复；此前超时和离线回放见[历史验证及失败](../evals/reports/auto-research-foundation-20260929/reading-regression/report.md)。

## 2026-10-02 Auto Research 原文定位

Auto Research的inspect在file/evidence类型下支持find_text：从offset开始查找首个大小写精确的字面文本，并返回该处原文窗口；例如按函数名定位定义，再用next_offset续读。它复用文件访问权限、脱敏、原始SHA和阅读覆盖记录，不执行正则或命令。未命中只说明指定范围没有该文本，不能据此推断实现不存在；命中也不表示已读完整文件或理解正确。

2026-10-02 补充：Auto Research重复检查以最近成功返回内容为依据；同路径源码或任务结果变化后允许复查，未变化则返回no-progress。首次失败与重复提示不覆盖已读版本；此记录只反映返回内容，不等于算法或结论已核验。

## 日常使用

- 直接提出问题，Agent 根据语义选择网络检索、资料库检索、历史或记忆。明确说“仅依据本地资料、不要联网”时，服务端禁用网络工具。
- 资料库使用 SQLite FTS5/BM25 与本机 BGE-M3 + Chroma 的融合检索。`retrieve` 返回短预览；`read_evidence` 打开原文，支持预览引用 ID 和 E 证据编号。页码与来源随证据保留。
- 对话中说“记住：比较论文时先给结论”，默认保存当前会话偏好；只有明确说“研究区记住：……”或在面板调整为研究区范围，才在本区新会话中共享。在“记忆与上下文”中查看来源、修改、确认、拒绝或忘记条目。也可说“忘记：具体条目内容”。忘记不删除原始聊天。
- 完成研究后，最多提取 3 条带逐字来源的候选结论；经过独立语义检查的条目标为“原文支持已检查”。它不表示事实永久正确。不同研究区不自动共享记忆。
- 同一会话的追问按逻辑轮次排队；后一条消息会在前一轮完成后理解指代。可重命名、归档/恢复，从历史消息指定位置建立分支。分支不会读到父会话后续消息。
- 研究运行中保存完整事件与已提交执行状态。中断或失败的研究任务可从有效检查点继续；已提交的只读工具结果不重放。无有效检查点或下载任务使用“重试”；下载会核对已有文件哈希。

## 上下文与计量

固定规则位于稳定前缀；变化的运行进度在末尾追加。输入预算达到约 80% 时，尝试生成结构化摘要，目标降到约 60%；原文、近期完整工具调用对和引用指针继续保留。摘要会检查结构、约束来源和证据编号；失败时保留旧摘要并明确降级。阈值是应用估计，不代表模型网关实际窗口，也不保证每次压缩恰好达到目标。

同步研究运行以 `user_message_end` 记录初始真实用户消息的边界，后续由程序追加的修订反馈不作为用户原话永久锁入摘要。旧检查点恢复时仅调整模型上下文投影，原始消息不改；当前段落修订契约和预算耗尽后的 `FINAL_ONLY` 约束放在受保护系统上下文中。跨模型恢复保留已有工具轮次的 reasoning 内容，对原供应商未提供该字段的工具轮次发送空字段以满足接口协议，不生成虚构推理。

每个请求分别记录路由、回答、压缩、记忆提取/核对的原始 usage、延迟及失败。缓存命中率只在供应商返回相关字段的请求子集上计算，同时显示字段覆盖率。没有缓存字段就是未知。没有供应商价格与真实账单，不把 token 换算为声称准确的费用。

## 启动与依赖

当前电脑已准备独立环境 `.venv-v3` 和固定版本 BGE-M3，不改动原 conda 环境与 `.env` 凭证。

```powershell
cd D:\project\researchagent
.\.venv-v3\Scripts\python.exe -B server.py
```

打开 http://127.0.0.1:8000/。也可运行 `start-researchagent.ps1`，日志在 `data/server-v3.out.log` 与 `data/server-v3.err.log`。

新机器的明确安装步骤：

```powershell
python -m venv .venv-v3
.\.venv-v3\Scripts\python.exe -m pip install -r requirements-retrieval.lock.txt
.\.venv-v3\Scripts\python.exe setup_retrieval.py
```

模型为 BAAI/bge-m3，revision `5617a9f61b028005a4858fdac845db406aefb181`，1024 维；CPU 默认最多 8 线程。模型文件约 2.3 GB。每段最多 512 tokenizer token（含特殊 token），重叠 64 内容 token。首次读取新资料需生成索引，明显慢于热查询；聊天请求不会自动下载模型。权重缺失或索引失败时保留关键词检索并显示降级状态。`RETRIEVAL_MODE=lexical` 可显式停用向量路径；`BGE_MODEL_PATH` 可指定已准备的同版本权重。

SQLite 是原文、记忆、会话的权威数据；Chroma 是可重建索引。不要在服务运行期间用第二个进程写同一 Chroma 目录。

## 当前边界

- 记忆编辑保留原消息与修改来源；目前没有自动语义聚类合并或通用冲突裁决器，冲突由用户确认。候选条目可在界面审阅，模型默认检索已确认或证据已检查的记忆。
- 归档目前在会话选择器中标记，允许直接恢复；不是删除。原始历史不因忘记记忆而擦除，显式历史回查仍可能找到历史文本。
- 对来源文件失效、哈希变化及作用域变化，读取原文时重新检查。保存在不可变运行证据中的研究记忆是历史结论，尚未实现按外部网页变化自动追踪其过时状态。
- 旧向量由 SQLite 回表校验排除，但尚未定期物理清理孤立记录；大量更新后可停服务重建派生索引。当前检索会检查当前研究区原始记录，未宣称全流程达到十万真实片段的稳定延迟。
- 记忆维护在现有单线程 worker 完成回答后执行，会推迟下一排队任务启动；没有独立优先级调度器。
- 恢复保证以已提交检查点为边界；工具返回但尚未提交的窗口可能重试只读动作，不提供供应商侧 exactly-once 保证。下载使用哈希核对，不能撤销已完成的外部操作。
- 真实评测仍有语义遗漏、来源不充分与网络失败，详见报告。压缩后的精确事实不保证零损失，需要时可回读原始证据。
- `read_evidence` 现在读取命中的原始段落，默认附带同一资料前后各一个原始段落（`adjacent=0..2`），每段独立保留页码、哈希和 E 引用。每段一次最多展示 1800 字符，按 `next_offset` 继续读；不会把相邻页的文字合并到同一页码下。

## 正文与回答质量修复（2026-09-18）

- 公共 HTML/text 下载上限为 2 MiB，传输和 gzip 解压都受限；模型输入仍按上下文预算摘录。空正文、纯导航和截断 HTML 返回 `incomplete_body`，不再生成“已读正文”证据。保留现有 DNS/重定向/SSRF 检查。
- 实际在线模型在交付前检查用户所问要点、主要事实和引用支持度。使用当前选择的模型，不带评测参考答案；搜索预览不能替代原文。最多两轮定向补读/修订，共最多三次检查，不增加工具预算。无法核实则保留已验证部分并说明缺口，任务标记为证据不足。
- 检查区分事实断言和认识边界：合理的“现有资料不足以确定”无需伪造引用，也不要求穷尽全文证明不存在。拒答中夹带的资料内容断言仍需正确引用；“整篇绝无某信息”等全称事实不能靠局部摘录证明。合理拒答可正常完成，相关 Claim 保持 INSUFFICIENT，不标成已验证外部事实。
- 检查结果和修订次数写入会话执行检查点，恢复时复用已检查的相同草稿，不重放已提交工具动作。检查请求以 `answer_verification` 单独记录，其 token、延迟和实际请求次数计入成本。
- 模型连接的 TLS EOF、临时断连/超时、429 和 5xx 最多重试两次，只重发当前模型请求。401/403、证书验证错误及格式错误不重试。退避 1/2 秒，Retry-After 最多等待 10 秒；每次物理请求保留 usage，未知消耗不写成零。
- 此检查仍使用模型，不能保证消除所有语义遗漏。修复前后正式评测保持原任务、参考事实、裁判提示和评分逻辑；旧 H3 离线探针曾要求“截断 HTML 仍成功”，该历史分数保持不变，现有回归明确断言新行为会拒绝该响应，不再宣称通过旧契约。

## 回答控制修复（2026-09-19）

- 路由先验证意图和字段类型，非研究意图的无关 `brief` 被清空，不改变该意图的工具权限；格式或字段矛盾最多纠正一次，纠正不能把已经识别的本地任务改为联网任务。
- `Evidence.provenance` 保存原文 artifact/chunk、页码、章节和行号，并通过 SQLite 新增列与会话检查点持久化。核验器直接读取这些元数据，不要求正文重复印出页码；页码标签和引用 ID 在程序中检查。
- 回答以不可变段落 ID 核验。首轮固定用户要求，后续保留要求清单；同一问题下未变段落及其证据可复用支持判断，仍检查全文覆盖和冲突。搜索摘要 E 编号不能通过 read_evidence 伪装正文，必须按返回的已授权 URL 调 read。核验缓存同时绑定草稿和证据集合，补读后会重新检查。核验器返回的唯一精确本地 ref 可映射回已有 E 编号，仍检查该段实际引用。修订只接受 `replace` / `append` 段落补丁，已通过段落由程序保留；补丁要求处于不可压缩的系统控制提示中。部分结果按原段落保留 Markdown，不用模型改述后的字符串反查原文。
- 核验分为 passed、needs_revision、unavailable。服务/JSON 故障停止内容修订，保存并明确显示待核验草稿，保持未完成状态，可从检查点续跑核验。不能把基础设施失败当成答案错误，不能把未核验草稿算作成功或提取为已确认记忆。
- 核验只发送引用的原文和最多四条补缺候选，2026-09-29起优先保留完整原文，仅在总体核验预算不足时缩减；此前无条件6000字符截断已撤销。搜索预览不进入原文核验。仍保留证据读取范围和截断信息。当前选择的模型兼任核验员，不能保证零误判。
- 研究循环总时间预算 600 秒；模型请求及重试共享剩余时间。核验逻辑调用总预算 90 秒，每次请求至多 60 秒，最多一次瞬时故障重试；其余请求仍最多两次重试。底层 urllib timeout 为阻塞操作超时，不是独立进程的硬实时截止；计量保留实际延迟。
- 评测中断后工具计数从执行检查点恢复，缺失 usage 继续单独记录。历史评分保留；原 72 次标准与拒答标准审计分别报告。新问题固定于 `evals/run_control_extensions.py`，不作为独立保密测试集。

本轮备份目录为 `data/backups/control-repair-20260919`。回滚只恢复应用源码，新增 provenance 列可保留；不能用升级前数据库覆盖新会话。

## 备份与回滚

部署前在 `data/backups/context-memory-20260918` 保存原应用文件、SQLite 一致性备份和部署清单。数据库使用新增表/列迁移，原有消息、任务、材料不重写。回滚应用时停服务、恢复备份应用文件、使用原 `evidence-agent` 环境运行；保留新增数据库列和用户新数据。只有尚无新写入且迁移失败时才恢复整个数据库备份，不能用旧数据库覆盖升级后新增的研究记录。

核验兼容相同要求的空白差异与重排，仍保存原要求文字；只接受唯一匹配且仅缺最后一位的段落编号，未知或含歧义编号仍拒绝。表格紧邻的来源说明与表格作为同一核验段落，普通独立事实段落不会继承别段引用。
