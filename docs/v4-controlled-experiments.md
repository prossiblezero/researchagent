## 使用

在「研究成果与实验 → 实验与基线 → V4 创建检索实验」填写待验证假设，保存后在方案版本旁选择最多1–3轮并点击「运行实验」。面板显示预算，点击即授权该固定方案。调用模型为 gpt-5.6-luna，凭据复用 .env 的 SUDOCODE_API_KEY/SUDOCODE_BASE_URL；不修改用户 Codex 配置。已有本机 Codex 0.155.0-alpha.9.2 和 elevated Windows 沙箱完成实测。其他平台保留 V3 功能，执行入口明确拒绝，不自动降级成无隔离执行。

默认注册 public-retrieval-feedback-v2：复用已有 FTS5/BGE-M3 父片段混合排序基线、6份公开资料、151段原文；新版本为24道开发题/12道同源新事实终验题，各覆盖不相交的6个事实簇，旧60题单列历史回归。开发阶段提供失败原文、URL/页码、词法匹配数、语义命中位置及可运行的 dev-eval.py；候选只能修改 ranker.py 和 proposal.md。旧 public-retrieval-v1（FTS5 分支，只修改 ranker.py）仍可显式选择。V3 手工实验配置仍仅录入，执行需要固定注册评测合同。可选关联已有创新候选的 idea_id；其研究假设不自动升级为事实。

可选 public-evidence-rerank-v1：宿主用已有 Luna 对最多40段候选原文进行无标签内容判断，编码代理只接收开发题的冻结 evidence_ranking。额外最多36次逻辑模型调用（传输错误可能在单题120秒内重试），四路并行，原始响应/摘录、调用用量和时间单列；缓存命中不会重复请求，失败也缓存。它增加模型开销。普通问答现有独立的 evidence_miss 待验证策略入口，遵守同模型质量/成本门槛；实验成功不会自动启用问答策略。

代码位于 experiments/<job_id>；合同、原文、JSONL、退出码、代码差异及测量在数据库旁 experiment-runs/<job_id>。均使用现有单 worker 队列；任务属于选择的独立会话，实验记录在研究区共享。按钮「刷新执行记录」查看最新状态、停止、恢复或新尝试。

## 合同与可信测量

复用 experiment_records/experiment_versions，只新增 experiment_runs 一张 SQLite 表。input_version_id、固定基线、数据/切分/评测器指纹、模型、文件范围与预算在提交时锁定。基线/实验原计划不覆盖；成功后分别生成实测版本，候选固定到这次实际测量的基线版本。结果版本与任务完成同事务提交，重复提交、执行代次变化和版本过期不会覆盖新结果。

固定评分器向候选进程传入语料与问题，不传入金标签，只接受有限且不重复的真实片段ID列表。宿主计算 Recall@5/MRR，模型最终说明不能作为分数。新终验9道可回答题参与主指标、3道无答案题单列；这些题来自6个事实簇，不能当作9个独立来源样本。历史40题仍按旧口径报告。151段原文保留URL/页码/哈希；命中不等于已阅读充分或回答引用有效。原有漏读与引用不足问题继续记录，不因检索实验成功而标为解决。

反馈套件只向编码阶段传开发题与开发语义信号，测试问题/标签留在宿主。精简开发工具输出包含指标、逐题变化和剩余失败；--full 可查看全部排名。先实现小候选、再根据开发反馈至多修订一次，属于同一次受控编码调用。dev-eval保存两版源码，编码收据绑定快照哈希；宿主各复算一次开发集，以基线初始化best，Recall@5/MRR均不下降才有资格替换，再按Recall/MRR选优。代码/结果/配置哈希保持一致；无效代码与退化版本保留在development-snapshots.json。锁定后才运行候选终验，终验结果不再传回本次编码代理。正式测量固定重复3遍，立即复制每次返回值并拒绝不稳定输出。Python 隔离进程显式使用 UTF-8，避免 Windows 默认编码改变中文输入。

语义信号一次准备并缓存，模型安装身份及信号哈希随合同/检查点保存；正式排序调用耗时、沙箱进程墙钟时间、语义信号准备耗时分别记录。反馈套件质量门槛为 Recall@5 至少增加1个百分点、MRR不下降，仍执行30秒进程上限；短进程启动噪声不参与质量门槛。计时是诊断信息，不是完整在线RAG延迟或抗恶意计费证明。

完成执行与达到目标是不同状态：实际调用、格式和完整性检查通过才能记录 WORKBENCH_MEASURED；是否达标继续使用已有比较器。没有自动启用候选，更不覆盖正式检索实现。

## 预算与隔离

- 默认编码1次，可显式选择最多2/3轮；默认总240秒、300000累计token（含缓存输入），可选30–600秒、2000–500000 token。CLI预算提醒加宿主完成后计量门禁，进行中的一次模型请求可能跨过token阈值；不承诺供应商请求可撤回或精确费用硬上限。超过阈值停止后续测量。
- 每轮至多2次开发复算；旧单轮保留原3次测量合同，多轮只对锁定最佳执行1次候选终验，每次30秒；实际非零退出、超时、取消、无效输出及不达标都保留。命令输出上限4MiB，文件单个2MiB/总计8MiB/500条目；不允许链接或合同外文件。Windows Job Object配置进程树退出清理、2GiB/32进程限制；没有虚拟机或磁盘配额。
- Codex命令使用显式权限、忽略全局用户配置与规则；禁用联网命令、apps/MCP配置继承、hooks、多Agent和记忆功能，保留模型服务通信。环境仅传必要变量，模型key不进入命令环境；凭据只供Codex宿主访问已配置模型服务。
- 本机elevated沙箱要求 :root read。仅实验目录可写，原项目data/evals/docs/.git、.env、Codex auth及SSH路径拒读；实验自己的.git只读。未屏蔽的其他系统文件仍可读，不宣称完整读取白名单或任意恶意代码安全运行环境。沙箱由Codex维护原生账户/ACL，配置失败即停止，不回退full-access。
- 实验初次提交、retry、resume均仅允许本机Windows请求。网页不接受工作目录或任意命令参数。

原文判断中已返回的在途响应先保存再响应停止，恢复复用缓存；已完成信号准备的任务累计保留用量，当前恢复的缓存命中另列。批次尚未整体返回时，已付费的部分响应仅在全局缓存，无法完整归属到具体任务；服务硬崩溃时尚未保存/返回的请求仍可能重复计费，不能承诺任意中断下零请求。

恢复只消费已保存的完整编码退出凭证（含代码及开发快照哈希）或代码检查点，不重新调用已消费的一次编码预算。退出成功、最终turn.completed才算编码完成；中间网络重连error保留为诊断。进程超时/不完整turn不能伪装为完成；新尝试另建job并重新授权预算。续跑还检查同方案排他性、最新版本、数据与环境指纹及代码完整性。编码用量按CLI turn单独汇总，不能冒充物理模型请求数，超时未知用量不计零。

## API

共同前缀 /api/spaces/<space>/research-records：

- POST /execution-plans：title、hypothesis、可选idea_id和suite，创建注册方案与固定基线。
- POST /experiment-versions/<version>/execute：conversation_id、authorize_execution=true、seconds、token_budget、可选max_iterations（1–3，默认1；旧FTS套件只允许1）。
- GET /executions、GET /executions/<job>；GET /executions/<job>/artifacts/<白名单文件名>。
- 取消、恢复和新尝试复用 /api/spaces/<space>/jobs/<job>/cancel|resume|retry。

旧 /experiment-versions/<version>/handoff 仍返回 execution_enabled=false：导出资料本身不授予执行权限。新增执行合同 research-execution/v1 指向固定输入、budget、workspace、authorization。已有开发选优决策复用同一合同及JSON状态，不替换会话、数据库或引入多Agent平台。多轮使用 research-execution/v2 并锁定控制器指纹；旧单轮合同仍可恢复。state.iteration 与 iterations.json 保存逐轮开发指标、预算扣减、停止原因和最佳代码；round-one/round-two/round-three 工件链接对应不可变轮次收据。已消费但缺少完整收据的编码不重放，用量不完整不追加轮次；终验中断不重放测试。
