# V1：隐式提问与连续追问

## 问题

用户在已有 Agent Harness 调研后询问“你知道 meta-harness 吗……为什么没有调研到呢”。真实意图记录把它判为 CHAT，回答声称“本轮没有检索工具”，要求用户再说“帮我核实”。这不是只能研究一次，也不是队列额度耗尽：分类提示混淆了路由步骤的能力和整个工作台的能力，也没有明确规定知识不足时自动补查。

## 解决方案

- 分类仍由 LLM 完成，不增加针对某个论文名的关键词开关。
- 明确工作台能联网，RESEARCH 会触发真正的搜索/阅读；分类模型自身不直接执行工具。
- 陌生论文、最新事实、对已有结果的遗漏质疑和缺少证据的追问自动补查；有名称即可先搜，不要求先提供链接或再授权。
- 新问题重新路由，旧回答中的能力声明和预算不是新规则；提供当前日期，历史年份仍需核验。
- 稳定常识、整理已给内容直接回答；信息问答中明确禁止联网时不搜索。
- quick 先简短告知正在查证，结果在原会话回复，单一问题优先短回答。

## 工作原理

最近会话历史 → 判断当前信息是否足够 → 直接回答或形成独立的补查简报 → 原有后台研究循环 → 结果追加到同一会话。每个新研究有独立任务 ID、预算、来源和过程；不会覆盖上轮结论。历史仅作为线索，不能代替新一轮的来源核验。

没有新增依赖或数据表。当前只复用最近会话历史，并未实现本地 PDF 文献库检索；需要打开本地文件、下载或执行实验仍保留相应能力边界。

## 试一下

1. “你知道 meta-harness 吗？”应自动检索并回复。
2. 接着问“它的代码开源了吗？”应结合历史补查，生成第二个任务。
3. “把上面的结果缩成一句话”应直接整理已有回答。
4. “不要联网，只凭已有知识回答，不知道就直说”应遵守限制。

可运行 `python -B evals/run_v1_routing_eval.py --live --workflow`，在独立数据库验证真实模型的 11 个路由案例和两轮连续研究。真实模型及搜索服务必须已配置，不用离线规则冒充语义路由验收。评测记录每个问题、预期意图、实际路由、任务和调用记录；流程通过不等于论文结论的学术正确性已评分。

- 最终离线回归：119 项单元测试通过，Stage 1 为 4/4、Harness 为 21/21、Stage 3–7 通过。
- [初轮真实验收](../evals/reports/v1-implicit-routing-live-network-20260916.json)：11 个路由案例、两轮工作流共 13/13；包括无明确检索口令、已有错误拒答的历史、常识、上文总结、禁止联网和未实现操作的边界。该轮执行的是简短提示调整前的版本，不能用报告末尾哈希宣称整个最终版本均已执行。
- [最终连续问答验收](../evals/reports/v1-implicit-followup-final-20260916.json)：2/2。两轮均自动选择 quick，在同一会话使用不同任务 ID，分别调用 6/7 次工具，均以 model_final 完成。查到论文 arXiv 页面和 Stanford IRIS Lab 的官方代码仓库。此报告在执行前记录源码哈希，已核对与交付源码一致。

简短回复采用提示约束，不是硬截断。实测答案仍可能超过建议长度；不会为满足字数删除来源或截断事实。以上有限案例不代表所有表达都能正确分流。
