# 完整项目回答质量与 LLM-as-a-Judge 校准（2026-10-13）

本报告分别记录完整项目配置的回答质量，以及裁判对预设标签的判定可靠性。四项质量指标描述项目交付的答案，校准准确率描述裁判；两者分别报告。简历介绍评测机制，具体数值、样本范围和失败记录保留在本报告中。

## 完整项目配置的回答质量

本节只统计2026-10-12评测快照中的完整项目配置，原始运行标识为 `integrated`：启用文档检索、混合历史检索、事实记忆与过程经验，使用 `deepseek-v4-1-flash`、temperature=0。复用该配置的全部20次首次评测运行（含失败），没有重新调用模型或选择较好的重复运行。

这20题来自既有后续资料问答面板，覆盖历史信息复用、跨资料比较、实验方法和证据不足场景。它最初用于记忆专项评测，本节采用其中完整配置的单组结果；这是完整项目在该20题面板上的质量记录，不是所有功能、全部320条任务或完整Auto Research流程的全量成绩。关键词配置的历史记录仍保留在原始证据中，本节不将其作为项目质量的前后对照。

沿用既有裁判提示的四项条件：事实正确、内容完整、引用充分、无实质性无据添加。最后一项取 `unsupported_additions=false`；拒答另有标记，合理拒答可以通过。每项分子为**成功交付，且有效评分确认达标的题数**，分母固定为全部20题；未交付和未知评分不计达标。四维不能相加或平均替代严格任务完成率。

## 裁判可靠性的预先冻结协议

新增[校准集](../../datasets/judge_calibration/v1.json)包含10个既有任务母题的80个受控变体，20个合格答案、60个不合格答案。覆盖同义改写、必答点遗漏、错误事实/算术、缺引用、错引用、无据添加、合理拒答与评分提示注入。参考事实及原文来自项目已有公开资料；第20母题没有原文片段，单独检验不编造本项目实测收益，不能声称验证了全部文献。

标签由实施代理依据原题、原文和既有裁判规则在运行前编写；另一代码审查代理在没有模型预测时完整盲审80题，未发现确定错标。不是独立人类标注，也不是80个相互独立的问题。数据只标注最终通过/不通过，不能据此宣称四个维度分别具有某个裁判准确率。

评分使用与上述质量评测逐字相同的 `JUDGE` 提示、相同 `model_json` 解析、`deepseek-v4-1-flash` 和temperature=0；仍调用实际模型服务。增加4096输出token上限、90秒单题期限、4并发，总900秒、120次物理请求和80万记账token。该输出上限与原质量评测不同，应保留这一运行条件差异。金标、标签理由、ID及变体分组不送给裁判；参考答案和原文是正常的裁判输入。

主指标为全部80题首次判定准确率，API失败、格式错误和未完成题均计错。另报通过/拒绝/未知的混淆表、有效负例误放行率、有效正例误拒率、判定覆盖率及Cohen κ。若有未知负例，同时给出将未知全部视为误放行的上界，避免超时把误放行率压低。Cohen κ和描述性区间仍受受控类别比例与题族相关性限制。

历史5例校准只作为烟雾检查，历史两模型11例复评只代表所选样本的10/11一致，均不能当作当前裁判的普遍准确率。此次也不校准运行时 `verify.py` 的另一套提示，结果只适用于本次离线评分配置。

## 复算及字段口径

评测脚本为 `evals/run_judge_calibration.py`；`tests/test_judge_calibration.py` 直接用已归档的40条质量记录和80条裁判结果重新计算指标，无需调用模型。相同测试还验证失败分母、金标隔离、请求留档和凭证脱敏。校准运行记录的源码哈希保持原样。

归档质量证据中的 `raw.valid_judgments` 为原始评分有效标记数；`reviewed.valid_judgments` 为合并已有原文复核后的有效状态记录数，**不能解释为完整四维评分覆盖率**。例如历史关键词组的 `memory-11/keyword` 是未交付且 `quality_assessed=false` 的状态复核，虽然最终状态有效，仍没有四维质量分数。所有质量分子同时要求产品成功交付及相应布尔字段满足条件，因此该记录不会增加任何质量达标数。

验证：在隔离分支执行 `python -m unittest tests.test_judge_calibration tests.test_intent_routing_eval`，14项测试全部通过；`python evals/run_judge_calibration.py --help` 正常。复算与测试不调用模型。
