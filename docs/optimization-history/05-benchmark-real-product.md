# 05 · 混合 benchmark 与真实产品评测

时间：2026-09-27—09-29。关键提交：`a7a4a38`、`9189511`、`c289f60`。

## 数据组织与评测勘误

将评测输入统一放到 `datasets/`、测试统一放到 `tests/`，运行结果存于本地 `evals/reports/`。组合 320 条任务：QASPER 80、SciFact 60、HotpotQA 50、LongMemEval 50、项目真实场景 80，并保存来源、切分、标签和许可证说明。

09-28 的早期比较使用手写规则代理，未直接调用真实产品，不能用作产品前后优化指标。09-29 改为 **296 条实际检索任务 + 24 项工程回归**，另冻结其中 32 题进行 64 次完整问答。原始结果与勘误保留，各轨道不合成一个总分。

## 实际产品检索

两臂均直接调用生产 `Retriever.retrieve`：baseline 为 FTS5/BM25，candidate 为 FTS5+BGE-M3+RRF；相同公开语料、top5 与 2000 token 预览预算，按父片段/会话去重。

| 留出轨道 | 任务 / 证据可评分 | Recall@5：基线 → 候选 | MRR@5：基线 → 候选 |
| --- | ---: | ---: | ---: |
| SciFact | 30 / 20 | 75.00% → 87.50% | 0.6042 → 0.7142 |
| QASPER | 40 / 28 | 44.46% → 52.32% | 0.3762 → 0.4637 |
| HotpotQA | 25 / 25 | 88.00% → 88.00% | 0.9400 → 0.9600 |
| LongMemEval | 25 / 25 | 8.33% → 37.47% | 0.0933 → 0.4060 |

SciFact 使用全部 5,183 篇摘要；QASPER 使用目标论文全文文本，映射不完整任务不计召回；HotpotQA 使用原有 distractor 上下文；LongMemEval 导入完整干扰会话并运行显式跨会话历史检索。LongMemEval 此处测历史召回，不是完整记忆问答准确率。均为固定子集，不是官方榜单。

## 完整 Agent 暴露新的瓶颈

同一 `deepseek-flash` 配置下，Workbench → LOCAL_QA → 检索 → 原文阅读 → 引用核验 → 报告/记忆全部真实执行。这一轨道的 baseline 关闭原文重排/阅读提示，candidate 开启二者，**不是上表的关键词与混合检索对照**。

首轮 32 题通过 **9/32 → 7/32**，主要问题是多工具协议适配和引用绑定，检索提高没有转化为整体问答提高。独立模型调用按答案、引用和无据添加评分，不称独立人类评审。

修复后在冻结的 SciFact 8 题 × 2 配置上重测：合计 **5/16 → 12/16（31.25% → 75%）**，多工具协议失败 **9/16 → 0/16**，修复后两配置均 6/8。该结果说明这组协议修复有用，不证明重排候选额外优势，也不覆盖原 32 题成绩。
