# 02 · V3：研究成果与证据版本化

时间：2026-09-21。后续随首次开发快照 `5ec0b27` 保存。

## 问题与改动

此前已经能检索、阅读和回答，但研究产物难以按版本审核，结论、假设、来源和实验配置需要长期关联。V3 在既有工作台上增量实现：

1. 报告不可变版本与草稿、审核、发布状态；修改另建草稿，旧正文和 Claim 快照保留。
2. Claim–Evidence–Source 关联，原文页码、获取时间、哈希、截断边界和验证状态可追溯；自动核验与人工审核分开。
3. 论文、项目、方法、数据集、指标、结论的关系展示，使用 SQLite 保存实体和关系。
4. 基于原文提出创新候选，必须区分研究缺口、假设、方法变化、预期收益、风险和验证方案，以 `HYPOTHESIS` 保存。
5. 基线、目标指标、实验配置和结果版本化；比较先核对数据、切分、种子、环境和单位，不把不可比结果直接判为提升。

发布是本地研究记录的状态，不等于公开发表或学术审核通过。本阶段未运行候选实验代码，后续执行能力在 V4 接入。

## 真实案例与结果

使用 ReAct、Retroformer 两份真实 PDF，研究动作前证据检查与失败反馈。Luna 完成两项假设候选，各有研究依据、风险、对照与消融方案。

## 失败、边界与决定

核验曾发现用错误片段支持“Wikipedia API”细节，要求修正引用；全部原始失败与修正均保留。已读内容仅为两篇论文中的相关方法/限制片段，不能声称读完 54 页全文或证明全领域创新性。生成的两个候选仍是未测量假设，未进入已确认记忆。

V3 没有替换检索、记忆、上下文和多会话模型，也没有引入图数据库。后续 Auto Research 将真实测量接入这里的版本与溯源基础。
