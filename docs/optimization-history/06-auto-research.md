# 06 · Auto Research：研究决策与 Coding Agent 工具

时间：2026-09-29—10-02。关键提交包括 `1656832`、`5beddf1`、`3d9c639`、`5371c6c`、`abc8a2e`；全部小步修改见[提交索引](commits.md)。

## 为什么重新设计

固定“编码 → 执行 → 比较检索指标”的循环，只能展示一种受控实验，不能完整表达研究 Agent 的价值。目标调整为：**研究模型按证据决定调研、保存假设与方案、调用 Codex、查看宿主测量、继续修订或结束**。Codex 是可委派的工具，研究问题和下一步决策由主控负责。

普通聊天、论文调研、资料问答与头脑风暴保留轻量入口，不强制进入实验。只有任务具有明确执行意图和能力范围时，才暴露可执行的编码与实验工具。

## 逐步补齐的能力

| 问题 | 实现与修复 |
| --- | --- |
| 工具返回后无法继续长研究 | 持久 CodingTool、任务 ID、等待/恢复状态与结构化失败收据。 |
| 代码写完仍由模型自报分数 | 宿主执行并绑定数据、代码、配置和指标来源；`assess_results` 根据实际测量分析。 |
| 每次实验都必须重新编码 | `run_experiments` 可重用已有代码；测量恢复与方法修订分别记录。 |
| 跨轮结果条件不一致 | 核对数据切分、源码、种子、生成参数等；同条件才进入比较。 |
| 研究产物游离在 V3 之外 | 测量绑定固定基线版本，保存报告与来源；跨任务证据带 job_id，未经验证的内容仍为 draft/unverified。 |
| 实验代码需要调用 LLM | 宿主管理凭据，通过 JSONL/stdio 模型接口代理调用；支持后请求依赖前回答，保存响应、usage 和失败。 |
| 长反馈淹没关键失败 | 限长压缩保留 measurement、失败题、条件和引用，提供宿主计算的诊断。 |

## 真实案例与发现

SciFact 案例打通调研、方案、真实编码委派、baseline/candidate/ablation 宿主测量和报告反馈，但早期有编码超时及额度失败。后续确实发生两版方案修订；独立审计发现多文档句索引未加偏移，影响 **47/809 个训练 claim**，因此保留为“流程运行、方法验证失败”的案例，未包装成正确方法收益。

QASPER 案例运行两版方案和 6 组宿主测量，评分复算一致；审计将原 Hit@5 口径改为严格 Recall@5，并指出基线非标准公式，不称论文忠实复现。宿主顺序模型接口也有真实请求验证，但接口接通本身不代表科研质量提高。

## 原文与恢复的持续修复

研究过程中继续发现读原文遗漏、来源脱敏后身份变化、代码修改后无法重新 inspect、引用修复缺少准确定位等问题。分别加入原始来源 SHA 与展示表示区分、连续读取窗口及 `find_text`、按文件版本重新读取、子研究证据目录压缩和引用错误定位。它们在 A-MEM 案例中进一步接受长运行验证。

当前方案仍是有边界的 Auto Research：预算耗尽、基础设施失败或假设不成立可以诚实结束；不保证自动完成高质量论文或达到 SOTA。
