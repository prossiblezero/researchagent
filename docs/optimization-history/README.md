## 如何理解这些结果

- **检索指标**衡量找到证据的能力；**完整问答通过率**还受原文阅读、生成、引用绑定和核验影响。两者分别报告。
- **工程回归**验证固定合同和错误路径；**研究实验**检验方法假设。测试全过不代表方法有效，代码执行成功也不代表研究成功。
- baseline、candidate 指各阶段明确写出的对照配置，并非永远对应同一套旧版、新版产品。不同题集、模型和评分口径之间不直接计算“全项目提升”。
- Recall@k 是前 k 个结果覆盖的标注证据比例；MRR 是首个正确结果排名倒数的平均值，截断到前 5 时记作 MRR@5；Answer F1 衡量预测答案与标准答案的词级重合，不能代替事实核验。
- 开发集、留出集和历史回归分开；无法回答的题不伪计为召回成功。保留首次失败、未知 token、复算修正和局部退化。

## 公开与本地档案

本目录提供可直接在 GitHub 阅读的阶段记录、结果表和来源指纹；原始报告、模型响应、Trace、实验工作区和大体积 ZIP 继续存于本地研究档案，未全部上传。`evidence-index.md` 中的代码路径用于在本地定位，故意不做成指向不存在文件的 GitHub 链接。SHA-256 用于确认所引用的文件版本，本身不等于第三方独立验证。

公开仓库从干净源码快照开始，未推送旧开发仓库的大体积 Git 历史。[提交索引](commits.md)记录全部现存开发提交的标识和摘要，但这些本地 SHA 不是公开仓库中的可检出提交。公开副本的提交另列。

旧阶段文档代表当时状态；当前使用方法以[项目 README](../../README.md)、[会话模型](../session-model.md)和当前实现为准。多会话始终遵循：研究区共享资料、Notes 和设置；会话独立；只有显式从历史消息分支才继承历史。

## 后续如何追加

每次有实质改动或一次冻结评测结束，新增日期记录或在对应阶段追加条目，写清：**问题 → 改动 → 对照与数据 → 结果 → 失败/限制 → 保留或回退的决定**，附实际代码版本及报告路径/指纹。修正指标时保留旧值及修正原因，不把失败覆盖为成功；仅文案变更可记在提交索引中。此目录随正常 Git 提交维护，不会自动采集本地运行。
