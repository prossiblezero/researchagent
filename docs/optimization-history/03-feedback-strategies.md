# 03 · 反馈驱动策略与引用恢复

时间：2026-09-21—09-23。关键提交：`5ec0b27`、`2a57f73`。

## 问题与改动

检索不到证据、读到但没引用、核验服务失败是不同问题。增加 SQLite 反馈、待验证诊断、不可变策略版本、逐题对照、启用记录与回退机制，候选策略包括查询规划、覆盖重排和原文阅读提示。候选只有满足质量、引用、延迟与计量门槛才启用。

冻结 6 份公开文档、60 个检索问题，其中 20 个开发、40 个历史控制；后者 30 个可回答、10 个无答案。另用同一 Luna 模型做 8 道真实问答的两臂比较。历史控制数据已参与过开发，不称新盲测。

| 指标 | 原混合检索 / 原 Harness | 查询规划候选 |
| --- | ---: | ---: |
| 历史控制 Recall@5 | 64.92% | 72.14% |
| 历史控制 Recall@10 | 75.87% | 89.76% |
| 历史控制 MRR | 0.570 | 0.625 |
| 最终真实问答通过 | 5/8 | 6/8 |
| 目标原文片段打开率 | 75.0% | 83.3% |
| 目标原文片段引用覆盖 | 66.7% | 83.3% |

## 失败诊断与修复

- 精确参数题基线草稿正确，但两次核验超时，最终没有通过；净增一题不能全部归因于检索。
- ReAct 列表存在事实已写出但列表段未绑定引用的问题，导致核验删除后答案不完整。后续修复列表引用绑定，保留已生成草稿与核验检查点，恢复时避免重复整答生成。
- 组合重排的排名召回更高，但实际片段送达率反而较仅查询规划低，不能只按排名分数选型。
- 基线存在 token 回报不完整；候选未通过自动启用成本门槛，不能将未知用量记为零。

## 决定

保留默认策略，将候选、失败与门槛结果版本化。记录的检索收益可用于描述局部功能效果；8 题真实问答结果仅作为小面板观察。后续围绕引用和原文读取继续修复，而不是把所有失败归结为 LLM 能力。
