# 01 · 工作台、检索、记忆与上下文

时间：2026-09-16—09-20。对应首次开发快照 `5ec0b27` 之前已完成的基础；这些日期来自验收文档，并非补造的 Git 提交时间。

## 问题与实现

最初已有 Agent Harness、工具调用、证据核验和恢复基础，需要成为可以长期使用的研究工作台。H1–H3 按文件迁入后，V1 增加研究区、会话、结构化意图、后台任务、取消/重试、重启恢复和报告落盘；V2 增加论文下载、本地资料导入、PDF 解析与原文问答。

随着长任务和多轮使用增加，进一步加入 SQLite FTS5 与 BGE-M3/Chroma 混合检索、资料/记忆/历史三类检索工具、结构化上下文压缩、原文回读、分支与检查点、带来源的记忆更新和遗忘。它们是持续增量开发，后续 V3/V4 复用这些基础。

会话设计经过修订后确定为：**研究区共享资料、Notes 和设置，区内可以有多个独立会话；从历史消息显式分支才继承历史。** 同研究区不等于自动读入所有会话历史。

## 当时的验证

| 验证 | 结果 | 说明 |
| --- | --- | --- |
| H1–H3 同步回归 | 88 项测试；H3 10/10 场景、118/118 断言 | 固定工程合同，不是开放研究准确率。 |
| V1 | 102/102 回归；离线 6/6、真实 4/4 工作流检查 | 4/4 为功能检查项，不是 4 道问题的质量评分；当时报告未独立语义标注。 |
| V2 真实任务 | 14/15 | 自编真实任务从首轮 6/15、中间 9/15 迭代至最终 14/15；不同修订非独立重复。 |
| 语义压缩 | 22/24；工具协议 24/24 | 精确事实并非全部保留，不能只展示协议通过率。 |
| 跨会话记忆 / 恢复 / 隔离 | 20/20、10/10、12/12 | 特定能力与确定性恢复检查，不是物理断电或任意场景保证。 |
| 早期混合检索 | 保留集 Recall@5 32.2% → 64.9% | 40 个同源保留问题中 30 个可评分；关键词对照混合检索。 |

## 失败与后续

真实 V1 曾出现未授权 URL、压缩摘要缺少模型协议字段、预算耗尽后继续请求工具等失败。分别保留授权拦截、补齐协议兼容、增加结束阶段总结约束，而未把失败草稿当完成报告。

早期“已检索”“已存入证据库”“模型已读完原文”容易混淆。后续持续改进实际阅读窗口、引用绑定和长上下文恢复；公开 benchmark 的真实产品验证后来在[第 05 阶段](05-benchmark-real-product.md)补充。
