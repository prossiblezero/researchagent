# 研究区、会话与执行：修订后的设计

研究区是共享论文、资料、Notes 和设置的工作空间。一个研究区可以包含多个会话；每个会话包含多轮交流。默认只展示一个会话，使用时仍然可以把整个研究方向当成一段持续研究。只有从已有历史位置继承内容的新会话，才叫分支。

上一版“一个研究区必须等于一个会话，旧独立聊天全部叫分支”的约束已撤回。旧聊天的 ID、内容、时间和真实父子关系全部保留，不人为建立继承关系。

## 依据与取舍

本次核对了官方 OpenAI 文档、Claude Code 官方文档，以及固定提交的 pi、Hermes 实现。不同产品并没有统一的 session 定义，借鉴的是可恢复、可分支和边界清晰的机制。

| 产品 | 可核查的设计 | 本项目采用的部分 |
| --- | --- | --- |
| Codex | Thread 包含 Turn，Turn 包含消息、工具等 Item；fork 新建 thread ID；当前文档的 sessionId 可把继承同一根的 thread 组成树 | 持久会话、多轮执行、流式事件分开，保留明确父子关系 |
| Claude Code | 新 session 独立开始；resume 沿用原 ID；fork 拷贝历史并使用新 ID；项目规则可以跨 session 生效 | 独立新会话与继承历史的分支分开，项目共享资料不等于共享全部聊天 |
| pi | 源码按 parentId 和分支 tip 选择 fork 内容，可复制单分支或整树的逻辑状态 | 只继承选定路径及截止位置，不带入后续消息；不引入其整套存储后端 |
| Hermes | session_search 从 SQLite 检索并阅读真实历史，支持按消息附近展开，工具自身不调用 LLM | 需要时检索旧聊天，并打开原文；不自动拼接所有会话 |

## 对象定义

| 对象 | 含义 | 现有存储 |
| --- | --- | --- |
| 研究区 / Workspace | 一个方向的共享资料、Notes、下载设置 | research_spaces |
| 会话 / Conversation | 可以独立续接的一段聊天历史 | conversations |
| 分支 / Fork | 继承某会话到指定历史位置的新会话 | parent_id、fork_event_seq；后者是兼容旧名称，实际存消息 ID |
| 一轮 / Turn | 一次用户提问及其相关回答和工作；可能发生多次模型请求 | messages.turn_seq、parent_message_id |
| 执行 / Job | 一次后台处理尝试，归属会话和原提问 | research_jobs；retry_of 关联重试 |
| 执行代次 | 同一 job 从检查点续跑时防止旧回调写回的标识 | execution_generation |
| 消息 / Message | 用户或助手的一条可读内容 | messages |
| 事件 / Event | 模型输出片段、工具开始/结果、验证等已发生的进度 | conversation_events |
| 上下文 / Context | 当前模型请求实际携带的历史、摘要、记忆和证据 | prompt_context 与检查点 |

```text
研究区：Agent 长期记忆
  ├─ 会话 A：论文综述 → 第 1 轮、第 2 轮……
  │    └─ 会话 A'：从第 2 轮回答分支 → 独立比较另一方案
  ├─ 会话 B：实验设计 → 从空白聊天开始
  └─ 共享：论文、Notes、报告、明确共享的研究区记忆

一轮提问 → 后台执行 → 多次模型请求 / 工具调用 → 流式事件 → 回答
```

“会话还在”不意味着每次请求都塞入全部历史。压缩只改变工作上下文，原始历史仍能查阅。停止一次执行也不关闭或删除会话。

## 操作语义

| 操作 | 行为 |
| --- | --- |
| 新建会话 | 留在当前研究区，聊天历史为空，共享该区资料和 Notes |
| 继续聊天 | 沿用同一会话 ID，追加新一轮 |
| 切换模型 | 应用于下一次请求，不创建或清空会话 |
| 从助手回答分支 | 复制到该回答为止的历史，使用新会话 ID |
| 从用户提问分支 | 复制提问之前的历史，把所选问题放回输入框；修改并发送后才产生新一轮 |
| 停止生成 | 取消当前会话正在运行与排队的任务，保留已保存历史；之后可以继续提问 |
| 重试研究 | 新 job，retry_of 指向原尝试；即使已有新问题，也仍归属原来那一轮 |
| 从检查点续跑 | 只接受有效检查点，沿用 job 并增加执行代次；记忆或历史失效时拒绝续跑 |
| 归档会话 | 从会话选择器收起，内容可恢复、仍可按需检索；不归档整个研究区 |
| 删除会话 | 可恢复地隐藏当前会话；已创建的分支副本和其他会话独立保留 |
| 删除一轮 | 隐藏该轮问题、回答及其任务/自动报告；分支副本不连带删除 |
| 归档/删除研究区 | 作用于整个共享空间，入口与会话操作明确区分 |

归档有未完成任务的会话会要求先停止。资料文件不会因上述可恢复删除而从磁盘清除。删除产生的可见性变化也会使相关摘要、记忆与检查点失效。

## 记忆与检索边界

- 会话记忆：`scope=session`，聊天来源须在当前会话已继承的历史中。“记住：……”默认采用此范围。编辑内容不再绕过来源约束。
- 研究区记忆：`scope=workspace`，在本区不同会话中共享。“研究区记住：……”或在面板明确调整范围后生效。
- 全局偏好：`scope=global`，只允许用户偏好；“全局记住：……”或显式调整范围后可跨研究区使用。研究结论不自动提升为全局事实。
- 早期没有会话来源的手工/资料记忆继续遵守原本的研究区共享行为；本次不猜测其不存在的历史归属。

`retrieve` 的三个范围：

| scope | history | documents | memory |
| --- | --- | --- | --- |
| current | 当前会话及已继承历史 | 本区共享资料 | 当前会话可见记忆 |
| workspace | 再包含本区其他会话 | 本区共享资料 | 按需召回本区其他研究结论；其他会话的局部偏好不自动沿用 |
| all_sessions | 再包含其他研究区 | 再包含其他研究区 | 扩大结论回忆范围；其他研究区局部偏好不作为记忆结果返回 |

跨会话命中带来源研究区与会话 ID，`read_evidence` 再查原始可见性。旧指令只作为历史资料，不能变成当前指令。明确“仅当前研究区”时允许本区历史，禁止跨区；明确“仅当前会话 / 不要跨会话”时同时禁止读取本区其他会话。

归档仍可回忆，回收站内容不参与检索。默认不会把其他会话拼入当前上下文；在需要历史证据时由 Agent 选择检索工具。

## 实现边界与后续判断

沿用 SQLite、FTS5、BGE-M3、Chroma、现有队列和事件流；没有新增服务、依赖或 API 密钥。`main_branch_id` 保留以兼容旧数据，只用作默认会话选择，不代表强制主线或继承关系。本次涉及会话、记忆、检索、前端与验证等超过 8 个文件，属于一致性修订，未替换整套运行时。

当前明确保留的限制：

- 停止是协作式取消，已经发出的远程请求可能等到返回或超时；不承诺取消服务商计费。
- 同一会话中新消息默认排队；没有实现 Codex 的活动轮次 steering。排队和实时纠偏不是同一种操作。
- 删除历史、调整记忆时，失效处理目前按研究区或全局范围进行，可能中断同范围其他运行中的任务。归档空闲会话不会中断其他任务。精确按证据依赖失效尚未实现。
- 跨会话检索复用各会话索引后合并；首次索引和大量会话会变慢。记录真实延迟后再决定是否建统一索引。
- SQLite 与事件记录保留真实历史，但不是新建的完整 event-sourcing 平台；网页断连重连复用已有事件游标。
- 界面切换保留未发送草稿；当前草稿只保存于页面生命周期内。

## 验证与回滚

验证新建会话历史为空、真实 fork 截止位置、同区回忆与跨区隔离、三级记忆范围、相同偏好的独立来源、重试仍归属原轮次、归档/回收站恢复、停止与流式回调隔离。完整回归沿用 Python unittest 与 Node 前端测试。

上线前保存源码与 SQLite 一致性备份，在数据库副本上重复初始化并核对原记录；有用户运行中任务时不直接重启。源码回滚可以恢复上一个版本；若已创建 workspace 范围记忆，需要保留当前数据并采用兼容读取，不能把旧数据库备份直接覆盖到新增用户数据上。
