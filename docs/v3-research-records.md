# V3：研究成果、创新候选与实验档案

## 问题

单次研究回答不足以支持长期积累：修订容易覆盖旧结论，创新预测容易与已有论文事实混淆，实验版本改变数据口径后仍可能被直接比较。

V3 沿用 SQLite、资料库、FTS5/BGE-M3/Chroma、原文阅读、上下文压缩、会话检查点及单 worker。研究区仍共享资料、Notes 与设置，可以有多个独立会话；只有从历史消息分支才继承聊天。以 [会话设计](session-model.md) 为准。

## 解决方案

木屋侧栏新增「研究成果与实验」，包含四个面板：

- **报告版本**：每次内容修改新建草稿，原正文和证据快照不变；可对比、导出 Markdown/HTML。草稿 → 已审核 → 已发布，状态操作必须有说明，历史操作追加记录。发布是本机报告状态，不会上传或公开网站。
- **结论与关系**：逐条查看 Claim 的自动验证结果、关联 Evidence、来源 URL、获取时间、类型、页码/章节、内容哈希及截断边界。论文/项目与结论的引用关系从现有数据导出；方法、数据集、指标等可手工添加，并选择结论和原文为关系提供依据。关系可以标为待核验、HYPOTHESIS 或人工审核。
- **创新候选**：聊天中提出创新问题。后台先从本研究区至少两篇论文读取原文，每篇整理两条关键事实并复用原有回答核验；随后生成研究缺口、假设、方法变化、预期收益、风险、验证方案。每项候选必须绑定至少两篇不同论文的真实 Claim/Evidence/原文片段。逐字片段和编号由程序检查，语义依据、假设边界和可证伪性由当前模型另次检查。无依据或核验不可用即失败，保留草稿和轨迹。
- **实验与基线**：保存基线/实验配置、目标、外部测量结果和失败原因；每次保存新建版本。实验固定到某一个基线版本，后来修改基线不会悄悄改变既有实验的对照。

候选始终是 `HYPOTHESIS`，不自动提取为已确认研究记忆。自动核验事实与人工审核状态分开显示：人工发布不会把原始 `UNVERIFIED` 结果改为 `SUPPORTED`。修改报告正文后，自动支持状态重新变为待核验，避免沿用旧正文的核验结论。

## 工作原理

新增八张 SQLite 表：`report_versions`、`research_record_events`、`research_entities`、`research_relations`、`research_ideas`、`experiment_records`、`experiment_versions`、`auto_experiment_measurements`。不引入图数据库、队列或新依赖。旧 `reports`、`runs`、消息、原文和文件继续保留；旧报告首次打开时建立内容快照。

报告快照包含正文及来源、证据、结论的不可变副本，并对正文和快照计算 SHA-256。状态是独立的可变字段，审核说明写入追加事件。编辑带最新版本 ID，避免旧页面覆盖新修改。已发布版本也可派生新草稿，但不会改写已发布内容。

报告版本作为历史研究资料进入已有检索索引，保留版本身份。`artifact_kind=report` 沿原文阅读传给核验器，历史报告只支持历史回忆，不能当作新外部事实的论文原文。创新原文仍须来自论文资料及其已核验事实。

创新使用现有后台执行、模型选择、流式进度和检查点。事实阶段未完成核验时可以从有效检查点续跑；创新生成/核验的请求计量和事件追加到同一运行轨迹。候选、报告和完成消息在一个 SQLite 事务提交，取消或执行代次改变后不会留下已完成候选。读取失败、核验失败不升级为成功，不强制凑出候选。

实验版本固定以下信息：数据集与版本、划分（train/validation/test/dev 或任务自定义标识）、划分标识/哈希、随机种子、代码版本、复现命令、环境、参数、指标定义、方向、目标及结果来源。保存命令只是记录文本，不执行。Auto Research 的有效宿主 measurement 在父报告归档事务中导入 `experiment_versions`，用 `auto_experiment_measurements` 保存任务/测量索引到版本的幂等绑定；无效或条件不完整的测量只记录跳过事件，不进入可比结果。

目标支持三种口径：

| 口径 | 含义 |
| --- | --- |
| absolute | 目标值本身，按越高/越低越好判断 |
| delta | 相对基线的改善差值，单位与指标一致 |
| relative_percent | 改善差值 / 基线绝对值 × 100；基线为零时未知 |

例如指标用 0–100 的百分数记录，delta=2 表示改善 2 个百分点；用 0–1 比例记录则 delta=0.02。不能混用单位。比较要求数据集、版本、划分及哈希、种子、环境、指标名/单位/方向一致，否则返回不可比较。训练命令、代码、参数及指标目标的变化会列出。仅当所选对照是实验固定的基线版本且双方完成测量时才判定达标；其他版本可以展示数值差异，但目标结果保持未知。未完成测量、失败实验、未知目标结果不会被标为达标；手工结果始终标为外部/用户录入，并不代表工作台独立复现。

## 试一下

1. 在本研究区准备两篇相关论文，保留原始 PDF；下载目录使用 `D:\paper`。
2. 新建独立会话，询问「仅依据本区两篇论文提出创新候选，不联网，明确依据和验证方案」。新会话不继承其他会话聊天，但可以读共享论文。
3. 打开「研究成果与实验」，阅读候选对应的具体原文及事实报告。修改报告另存草稿；实际核对后填写审核说明，再发布。
4. 建立基线，填写冻结的配置与目标。建立实验时选定基线版本和候选；已有外部实验结果可以录入，并写清日志位置、测量时间与失败原因。
5. 比较两个版本；改变划分或指标单位再保存一版，可看到系统拒绝以不同口径判定达标。

所有接口位于 `/api/spaces/{space_id}/research-records`，继续执行现有来源与研究区检查：

| 方法与路径 | 用途 |
| --- | --- |
| GET `/reports`、`/reports/{report_id}` | 报告列表、内容版本、覆盖指标和操作记录 |
| POST `/reports/{report_id}/versions` | `{base_version_id, content, note}` 创建草稿 |
| PATCH `/reports/{report_id}/versions/{version_id}` | `{status: reviewed/published, note}` 记录审核或发布 |
| GET `/reports/{report_id}/compare?left=…&right=…` | 比较正文版本 |
| GET `/reports/{report_id}/versions/{version_id}/report.md` 或 `report.html` | 导出指定版本及证据 |
| GET `/graph`，POST `/entities`、`/relations` | 对象与带依据关系 |
| GET `/ideas` | 有效会话来源中的创新候选 |
| GET/POST `/experiments` | 列出/创建基线或实验 |
| GET `/experiments/{id}`，POST `/experiments/{id}/versions` | 查看/创建实验版本 |
| GET `/experiment-comparison?left=…&right=…` | 比较指定版本 |
| GET `/experiment-versions/{id}/handoff` | 导出 V4 交接合同 |

引用依据的输入格式是 `{report_version_id, claim_id, evidence_id, span}`；`span` 选取该 Evidence 中现有的逐字分段。服务端检查真实绑定和作用域，拒绝未知引用、搜索预览和跨区 ID。实体与关系使用原生列表/表格展示，适合当前单机资料规模。

## 接下来与边界

V4 交接 JSON 标识为 `research-experiment/v1`，包含不可变实验与基线版本、指标和结果回传要求；`execution_enabled=false`，工作目录、允许路径和资源预算留空。当前 Auto Research 已补充宿主管理实验模型接口：实验代码可生成请求 JSONL，宿主在沙箱外按预算调用模型并写回响应，凭据不进入实验环境；接口合同和收据见 [v4-host-model-interface](v4-host-model-interface.md)。后续执行器仍必须先补齐授权及资源合同，不能把 V3 中的命令字段直接当作可执行指令。本版没有自动写代码、执行实验或迭代优化。

没有穷尽检索来证明全领域新颖性；模型核验也不是零误判保证。片段读取不代表通读全文；PDF 表格、公式、图像保留既有解析限制。关系的人工审核是用户声明，自动关系仅表示既有结论对原文的引用。报告来源快照证明当时保存的内容，不代表来源网页至今未变。

实验种子及结果由录入方提供，目前保存聚合指标，不自动计算统计显著性、置信区间或验证外部日志真实性。单机图谱以现有 SQLite 查询与派生关系实现，大量报告时再根据实测性能考虑批量索引；不提前引入外部图服务。

源码与数据库升级前备份位于 `data/backups/roadmap-v3-20260920-232641`。回滚应用源码可保留新增表；不要用旧数据库覆盖升级后新增的会话或研究成果。242 项后端、24 项前端及 V1/V2/Stage 1–7 回归通过。真实 ReAct/Retroformer 案例生成两个 HYPOTHESIS，8/8 引文逐字匹配，效果未实验验证。验收及保留失败见 [V3 验收报告](../evals/reports/roadmap-v3-20260921/report.md)。
