## 目标与边界

做一个日常可用、按需自主推进科研的研究 Agent。聊天、问论文、调研领域和头脑风暴各自在请求范围内交付；只有明确要求自动调研、实现、实验和迭代时，才进入 Auto Research。研究区共享资料、Notes 和设置，允许多个独立会话，仅显式从历史消息分支才继承历史。保持 SQLite、已有检索/记忆/压缩能力、木屋界面、用户数据和 .env；下载使用 D:/paper。

给定“研究 Agent 方向，以 CVPR 质量为目标”等课题，研究 LLM 应读近期论文、报告和技术分析的原文，理解核心方法、输入输出、数据集、代码和局限；提出有依据的缺口及待验证假设，选择较新且可复现的 baseline，设计方法、对比和消融。用户要求三个创新点时，应形成同一课题中三个可分别验证的贡献，而非三个无关选题。证据不足时明确缺口，不能将假设表述为已验证事实。

Codex CLI 是研究 LLM 按需调用的工具。研究 LLM 决定何时交接实现方案、如何解释实测结果、是否补调研/改方法/再实验或结束；宿主负责授权范围、预算、持久状态及实际执行和测量。最终应交付代码、数据/配置版本、方法沿革、实验比较、来源、运行轨迹和可复验报告。不能承诺任何开放课题必得 SOTA 或录用，但必须保留完整研究能力和实证验收要求，不能用一次排序脚本通过代替。

项目也服务求职。简历使用已有真实成果，后续用更强证据替换；不必为 Codex 接入另造提升指标，不把外部编码模型能力归为自研 Harness 收益。设计依据见[V4修订](auto-research-v4-redesign-20260929.md)和[会话模型](session-model.md)。
