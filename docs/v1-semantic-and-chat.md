# V1：语义研究计划与对话交互

日期：2026-09-16。项目：`D:\project\researchagent`。

## 问题

用户无法稳定选中、复制对话或回答，输入框仅支持 Ctrl/Command+Enter。页面每 1.2 秒刷新；旧更新逻辑直接比较生成的 HTML 与浏览器序列化后的 innerHTML，含引号等转义字符时即使内容不变也会替换节点，从而破坏选区。新消息到来时，旧实现还会重建整段历史。

研究虽然已有 LLM 路由和工具选择，但指导重点在来源与预算，未明确要求先定义研究问题和语义相关性。代码并没有“标题必须包含关键词”的过滤器；模型可能采用过窄查询、按题名判断，或对旧遗漏猜测原因。仅把 agent 换成 model 无法解决召回与相关性判断问题。

## 解决方案

- 提问、回答、输入草稿、研究结果均可一键复制原始文本，保留 Markdown 和换行；剪贴板 API 不可用时尝试浏览器原生复制，失败会提示。
- Enter 发送，Shift+Enter 换行；保留 Ctrl/Command+Enter。中文输入法组字/选词期间的回车不发送，长按回车不重复提交。
- 历史消息按 ID 更新，新增消息不会重建旧消息；HTML 更新缓存原始输入及浏览器实际序列化值。研究结果及计划内容未变化时也不重新写入。
- 利用现有路由请求生成可检查的研究计划：目标/对象/机制、纳入与排除标准、不同检索路径。计划仍存于 brief，无新增数据库字段或额外规划请求。执行同时保留原始用户问题，避免压缩后的简报替代真正需求；重试保留原计划。
- 按术语/别名、功能描述、方法机制、任务/评测等角度发现候选，根据摘要和方法判断相关性。单篇已知论文先精确定位，不机械执行全部路径；找到足量代表论文后集中阅读核实。
- 最终说明具体机制与用户问题的联系，并附证据。标题缺少关键词不能作为排除条件；相关术语也不自动视为同义词。只有见到旧查询/候选/筛选记录，才能断言漏检发生在哪一步。

## 工作原理与边界

这是 LLM 驱动的语义规划、查询扩展及证据判断，底层仍使用既有搜索服务。没有新增向量库、专用学术 API 或写死论文清单。查询覆盖和论文理解仍受模型、搜索索引、可读取内容与预算影响；不能承诺穷尽论文或把工具成功率当作论文召回率。

短研究计划展示目标、路径和判断依据，不展示模型内部思维过程。原始网页继续视为不可信资料，read 的 URL 授权边界、引用核验、取消、预算和模型选择保持生效。

真实验收还发现 AAAI 页面返回 gzip 字节却未声明 Content-Encoding。HttpReader 现在支持声明 gzip 或带 gzip 文件头的响应，解压输出仍受原字节上限约束，截断明确标注，损坏数据不作为证据返回。没有放开网络边界或 PDF 限制。研究指导另外明确 S/E 编号不可重排，简要比较不另造来源清单；这不替代独立的引用语义核验。

## 验证

- `python -B evals/run_all.py`：130 项单元测试通过；Stage 1 为 4/4，离线 Harness 为 21/21，Stage 3–7 通过。新增检查原问题和语义计划能够传到实际研究调用，持久化/重试不丢失计划，以及 gzip 解码、解压上限和损坏数据拒绝。
- `node --check web/app.js` 和 `node --test tests/test_workbench_frontend.cjs`：3 项前端行为回归通过，包括输入法确认、换行、发送、防长按重复、转义字符导致的重绘。
- 独立本地浏览器测试：提问/回答/草稿/报告的剪贴板内容逐字匹配；Shift+Enter 只换行，Enter 新增一条提问；含引号的内容保持稳定；跨轮询保留报告选区，Ctrl+C 与选中文本一致。使用独立数据库，不向用户会话写入验收消息。
- [首轮真实报告](../evals/reports/v1-semantic-live-20260916.json)的自动工作流指标为 2/2，但第二例人工核对未接受：能找到题名不含 memory 的 Reflexion/ExpeL，却将 S/E 编号重新编排，引用与实际记录不符，AAAI 阅读证据还是未解压字节。因此不能把该轮“completed”称为质量通过；原报告及证据完整保留。
- [修正后真实报告](../evals/reports/v1-semantic-live-final-20260916.json)：工作流 2/2。Meta-Harness 案例使用 2 次工具，读取 arXiv 原文，按机制解释其与记忆、上下文和自改进的联系；未编造旧轮遗漏原因。经验复用案例使用 10 次工具，实际查询包含 reusable experience / feedback / strategy / experiential learning / skill library 等不同角度，读取 ExpeL、Reflexion 和 Voyager 的论文/项目页。最终按跨任务复用标准选择 ExpeL 和 Voyager，明确 Reflexion 偏跨试次纠错，因此未仅按题名关键词选论文。
- 逐项核对最终案例的 S/E 绑定：Meta-Harness 为 S5/E6；ExpeL 原文为 S17/E27，Reflexion 为 S23/E28，Voyager 官方项目为 S28/E34，均与实际存储记录对应。回答仍混用少量二手摘要，且比较答复偏长；未做全篇结论正确率或领域召回率评分。
- AAAI 原链接独立复测返回正确标题与 2,853 字符文本，无替换乱码、未截断；此前该链接的压缩响应只有 4,940 字节且没有 Content-Encoding 声明。真实测试使用现有 Sudocode Luna 与搜索配置，原始输入及输出保存在独立数据库和 Trace。
