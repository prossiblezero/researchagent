# V2：原文资料、论文分析和本地问答

更新日期：2026-09-18。项目：`D:\project\researchagent`。本阶段继续使用已有 SQLite、后台工作线程、模型选择和木屋界面。

## 问题

V1 的阅读工具只接受 HTML/文本，论文 PDF 不能进入研究上下文。下载根目录只保存设置，用户也无法把自己的论文纳入研究区并按原文追问。研究结果、搜索摘要与全文证据容易混在一起。

## 解决方案

V2 加入独立的资料库。入口位于左侧研究区下面，不改变聊天和 Notes 的双栏布局。可添加论文页、PDF、技术文档和 GitHub 仓库，也可用系统文件选择器导入 PDF、Markdown 和 UTF-8 文本。所有原始文件都复制/下载到当前研究区配置的目录。

- 论文页的 `citation_*` 元数据提供题名、作者、年份、DOI、PDF 链接及来源声明的会场。arXiv 单独标记为预印本；会场声明仍需交叉核验。没有找到的元数据不猜测。
- PDF 按页提取文字，识别摘要、引言、方法、实验、结果、局限、结论及参考文献。每条本地片段有稳定的 `L` 编号和页码/行号。
- 分析区分“原文依据与作者表述”和“Agent 推断与建议”，展示阅读覆盖范围和缺失证据。模型从实际提供的原文分段中选择 L 编号与 span 编号，程序按编号提取精确原文；保留对旧 quote 格式的逐字验证（忽略空白与大小写）。结构或引用错误最多纠正一次，仍不合法则明确失败。这检查引用位置，不等于已经证明概括的语义正确。
- GitHub 使用公开 REST API 获取固定 commit 的目录树，并通过 Contents API 读取同一提交的文件，分别选取 README、依赖、入口、测试和关键代码文件，总计最多十个。只阅读；明确勾选保存时才下载该提交的源码 ZIP。不是完整 Git clone，不安装依赖、不运行代码、不声称测试已经通过。
- 本地问答先由模型理解问题和会话指代、选择相关资料并生成中英文检索词，再检索片段并回答。只使用当前研究区的资料，不调用网页搜索。事实回答附文件路径、章节、页码及可点击的原文摘录链接。
- 既有研究报告会自动建立本研究区的索引，并标记为 Agent 报告，不能当作论文原文。

## 工作原理

```text
研究区设置（目录、自动下载、篇数/容量）
    ├─ 对话 → LLM Router → RESEARCH / DOWNLOAD / LOCAL_QA
    └─ 资料库 → URL / 文件选择 → MATERIAL
                         ↓
              原有 SQLite 队列与一个后台线程
                         ↓
     公网校验 → 获取原文 → 按页解析 → document_chunks
                         ↓
           分析 / 本地问答 → 摘录校验 → citations
                         ↓
           对话回复 + Notes + 资料阅读页 + Trace
```

数据库只新增字段、`artifacts`、`document_chunks` 和 `citations`；保留原有 runs、消息、研究区和任务。任务增加 `kind` 与 `payload`，取消、重试、中断恢复仍沿用现有机制。`DOWNLOAD` 可以从本次消息 URL、会话来源中选论文；给出论文名称时可做一次定位检索，不能自行编造链接。`BRAINSTORM`、`EXPERIMENT` 仍待 V3/V4。

本阶段修改范围超过八个文件，涉及获取/解析、资料索引、工作台路由、HTTP API、页面、测试和教学文档。只新增一个 Python 依赖：`pypdf==6.19.0`。未引入向量数据库、OCR 服务或新的任务队列。

### 文件、下载和读取边界

默认预算为每次最多三篇、合计 50 MB；可设为 1–20 篇、1–500 MB，单个文件硬上限 25 MB。现有研究区升级后自动下载保持关闭；用户保存目录、预算并开启选项后，研究结束会按相关性选择经典、代表性和最新论文。某类没有合适资料时不会凑数。技术文档和 GitHub 不会被自动下载为论文。

归档示例：

```text
授权根目录/
  研究区名称-ID/主题/论文/年份-标题-唯一后缀/
    原文.pdf
    报告.md
    metadata.json
```

路径组件会清理 Windows 非法字符、保留设备名和目录穿越。每次写入和下载前校验实际解析后的路径；文件完成到临时文件后原子发布，不覆盖已有原文。按研究区内 DOI/arXiv ID/规范 URL 以及 SHA-256 去重。上传/下载原文被外部修改、删除或不在当前授权根目录时，禁止据旧索引冒充当前文件回答。更改下载根目录不会搬移文件；旧目录资料需重新导入。删除研究区仍只删除数据库关联记录，不递归删除用户文件。

网络获取复用 Harness 的公网 DNS 检查和固定 IP 连接。每个重定向重新校验，拒绝凭据 URL、内网、网络共享、非支持类型、超限和不完整内容。不会绕过登录或付费。GitHub ZIP 不解压，因此不执行其中的代码或归档路径。

PDF 在独立子进程解析，60 秒超时；最多 200 页、500,000 个文本字符。扫描页、低文字页和提取异常保留页码并列出警告。未实现 OCR，未验证任何页中的公式、图表或表格结构。结构化分析最多使用 32,000 字符的片段，优先覆盖不同章节；不会把未提供给模型的全文说成“全部读懂”。本地问答最多选择八份资料、30,000 字符片段，检索规模扩大后再评估 FTS/语义检索后端。

### API

| 路径 | 用途 |
|---|---|
| `GET /api/spaces/{space}/materials` | 当前研究区资料列表；同步历史报告索引 |
| `POST /api/spaces/{space}/materials` | 提交 URL 阅读/下载，或已有资料的分析任务；携带 conversation_id、model_id |
| `POST /api/spaces/{space}/materials/upload` | 同源 binary 上传，query 提供 filename/conversation_id/model_id |
| `GET /api/spaces/{space}/materials/{id}` | 元数据与分析 |
| `GET .../{id}/chunks` | 本地片段及页码/行号 |
| `GET .../{id}/reader` | 暖纸色阅读页与原文摘录 |
| `GET .../{id}/original` | 只允许访问已登记且仍处于授权目录的文件 |
| `GET .../{id}/analysis.md` | 下载分析笔记 |
| `GET /api/spaces/{space}/jobs/{job}/local-evidence` | 该任务的本地引用与所处理资料 |

上传文件默认由当前前端模型分析；仅在已有 `.env` 中配置的模型范围内选择，无需新增 API key。

## 试一下

```powershell
conda activate evidence-agent
python -m pip install -r requirements.txt
python server.py
```

1. 打开工作台，进入“研究区设置”，选择资料保存文件夹，设定下载篇数与容量。希望研究后自动收集论文时，勾选自动下载。
2. 点击“研究资料库”，输入论文页或 PDF 链接；需要落盘时勾选保存。或者直接选择本地 PDF、Markdown、文本文件。
3. 回到 Notes 的“实时过程”，查看实际下载、提取、分析阶段。
4. 在书架打开阅读页，核对原文、解析边界、分析和页码。重复添加相同 PDF 不应覆盖或产生另一份原文。
5. 点击“询问这份资料”，补充问题；或者直接问“根据本地论文解释方法及局限，并引用页码”。答案中的证据链接会跳到对应原文片段。

## 对照资料

- [Docling Technical Report](https://arxiv.org/abs/2408.09869)，2024 年 arXiv 技术报告（预印本）。本次确认官方题名；用于明确 PDF 版面解析、OCR、表格与纯文字抽取不是同一能力，本版本不声称复现 Docling。
- [Docling DocumentConverter](https://github.com/docling-project/docling/blob/main/docling/document_converter.py)：本次读取转换入口，采用“提取结果与转换/解析状态分开记录”的做法；没有引入其模型管线和依赖。
- [GitHub Repository Contents API](https://docs.github.com/en/rest/repos/contents)：本次查阅官方只读文件接口；实际实现将所有文件固定到 commit，并明确记录读取范围。
- [pypdf](https://pypi.org/project/pypdf/6.19.0/)：已从官方 PyPI 安装并用测试中构造的四页 PDF 验证提取。在线 extract-text 文档当次返回 403，因此不把网页文档查阅写成已成功。
