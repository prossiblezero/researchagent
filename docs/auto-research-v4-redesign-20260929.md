# V4 修订：可选的 Auto Research 与 Coding Agent 工具

日期：2026-09-29。最新状态：研究控制器、持久CodingTool、项目准备与产品入口已接通；后端400/400、前端32/32，真实原生准备和Luna路由7/7通过，首次完整SciFact课题以blocked结束、未通过验收。本文件其余内容保留设计时点，文中的拟定规模/指标不是已完成成绩；当前实现与剩余边界以[目标差距](auto-research-goal-gap-20260929.md)及[验收记录](../evals/reports/auto-research-foundation-20260929/report.md)为准。

最新定位：按用户补充，Codex CLI 采用 agent-as-tool 方式接入，是完成 Auto Research 的执行工具。研究侧 LLM 在任务授权范围内决定何时委派编码、复现或实验，以及何时继续调研。工具接入以真实功能验收为主，不为接入单独追求提升指标；本文件的三组归因评测仅作以后评估整体研究编排的可选方案，不作为功能交付或简历描述工具集成的前置门槛。

## 1. 产品目标与现状

用户目标是：调研最新论文、报告和代码 → 提炼证据与研究缺口 → 选择可复现 baseline → 提出方法与创新假设 → 设计对比和消融 → 交给 Codex CLI 实现 → 宿主执行并核实指标 → 研究 Agent 根据结果决定修代码、修方法、补调研或结束 → 输出研究报告。研究 Agent 管理研究方向、证据、方法和实验决策；Codex 是可复用的编码执行组件。

设计修订前，实验执行仅支持固定注册的检索/重排合同，选优依赖Recall@5/MRR。当前已在既有调研、证据与执行基础上增加通用项目准备、模型驱动研究控制器和结果回传；“结果→补调研→新版方案”已有代码及夹具测试，真实课题和研究级实验可靠性仍待验收。完整Auto Research尚未完成。

历史 9 道终验题 Recall@5 88.89%→100% 是一个排序候选的实测收益。模型、研究材料、外部语义信号、代码和选择规则共同影响它；既不能把它单独归功于 Codex，也不能把它当作自研研究 Agent 的独立贡献。现有 SciFact/QASPER 的生产检索消融仍然有效，其比较对象是检索配置，与上述编码实验归因分开。

## 2. 入口与任务范围

保留现有 CHAT、RESEARCH、LOCAL_QA、DOWNLOAD、BRAINSTORM、EXPERIMENT；新增 AUTO_RESEARCH 作为任务意图，不把整个研究区或会话永久切换成自动实验模式。

| 用户表达 | 行为与停止点 |
| --- | --- |
| “解释一下这篇论文”“讨论一下这个方法” | 沿用聊天、本地问答或必要的补查；回答后结束 |
| “调研最近 Agent memory 的论文” | 按范围检索、读原文、比较并交付综述；结束，不创建代码实验 |
| “给我三个 idea”“为这篇论文设计消融” | 输出有证据的候选或实验设计；没有执行请求就停在方案 |
| “我想发 CVPR，先帮我看看方向” | 先做方向调研；发表愿望不等于执行授权 |
| “把这个方案交给 Codex 实现并跑实验” | 执行用户指定方案；没有要求自动研究时不扩展成开放研究循环 |
| “围绕这个目标自动调研、实现、实验，根据结果继续迭代” | 建立 Auto Research 任务，沿用已明确的资源范围与预算自动推进 |

按语义和当前任务判断，不能靠“论文”“研究”“创新”“CVPR”关键词自动升级。明确“只调研”“暂不实现”限制优先；不强制用户先选模式或填实验配置才能聊天、调研。只有执行所需目标、工作区或预算确实缺失时，在启动有资源消耗的实验前补齐，不重复询问已授权条件。

Auto Research 运行中，新消息仍按用户意图区分：状态询问/解释结果按 CHAT；“继续这项研究”恢复指定任务；“只补查这篇论文”启动单次研究，不暗中扩大正在运行的实验。每次决策绑定 campaign 与目标版本，避免其他会话的提问被当作新实验指令。

研究区继续共享资料、Notes 和设置，允许多个独立会话；新会话不继承聊天历史，从历史位置分支才继承。不引入“一个研究区只能有一项自动研究/一条会话”的限制。

## 3. 最小架构与研究循环

推荐在现有 Workbench、SQLite、任务队列、Trace、V3 研究记录和 Codex 执行器上增加一个显式研究控制器。研究 LLM 自主选择检索、原文阅读、方案记录和 Coding Agent 工具；控制器负责持久化、工具可用范围、预算及任务推进，不以固定阶段顺序替代研究判断。无需新服务、图数据库或多 Agent 框架。最小实现先跑通一个完整研究课题，包含实际结果回传；用另一个明确需要调整的案例验证方案修订，正常任务不为了凑迭代次数而强制重做。

```text
当前用户请求 → 意图与范围
  ├─ CHAT / LOCAL_QA / RESEARCH / BRAINSTORM → 现有流程 → 本次交付
  ├─ EXPERIMENT → 指定实验 → 测量与交付
  └─ AUTO_RESEARCH → 研究控制器
        调研与证据 → 基线选择/复现 → 方法与实验计划
                   → Codex 实现 → 宿主实验与结果核实
                   → 研究决策
                      ├─ 修复实现 → Codex 实现
                      ├─ 补充原文/改变假设 → 调研与方案新版本
                      ├─ 补足对比或消融 → 实验计划新版本
                      └─ 目标达成 / 预算耗尽 / 受阻 / 用户取消 → 报告
```

研究控制器产生结构化、可核对的决策依据，保存证据与原因；不保存或展示模型私有思维链。下一步动作限定为补调研、重设计、复现基线、实现、补实验、完成、受阻和停止，由宿主验证作用域、预算及前置条件。

上图表示可能的研究路径，不是必须逐站执行的固定流水线。LLM 可以先委派 baseline 可复现性探测，再针对探测结果继续读论文；也可以认为现有证据已足够，记录实现方案后直接委派。不能用“搜满 N 篇”或固定轮次决定调研是否结束。宿主仅验证有效方案、目标/输入、授权范围、预算和验收条件等可检查要求，不硬编码论文数量作为调用门槛。

### Coding Agent 工具合同

- **何时可用：**Auto Research 已授权执行，或用户明确要求实现/实验时，将 Coding Agent 工具加入当次可用工具集。CHAT、仅调研和仅头脑风暴任务不暴露可执行的委派工具；宿主同时核对能力范围，不能只依赖提示词。AUTO_RESEARCH 是允许使用工具的条件，不代表一进入就必须调用。
- **谁决定调用：**研究 LLM 根据原文证据、现有代码、研究目标和上次结果，决定委派的时机及内容。先保存与本次委派对应的方案版本；若只是 baseline 探测，记录复现目标和检查项即可，不要求先完成全部创新设计。
- **输入：**目标与方案版本引用、实现/复现/实验子任务、所需来源与代码引用、验收条件、期望产物。工作目录、允许的操作和最大预算从宿主已授权合同解析，LLM 只能分配剩余范围内的资源，不能通过工具参数自行扩大权限。
- **执行：**适配器调用本机 Codex CLI，由 Codex 在隔离课题目录中自主完成局部编码、调试及获准的实验操作；复用现有进程、取消、收据和恢复基础。研究 LLM 无需逐条生成 shell 命令，也不必接收 Codex 的全部中间上下文。
- **返回：**长任务先返回持久 job_id 与运行状态；完成后把结构化工具结果送回同一研究任务。结果包括已完成工作、代码版本/差异、实际命令与退出码、日志/产物路径、指标来源、用量、失败和未完成项。Codex 自报指标与宿主已核实指标分开，未核实结果不能用于宣称达标。状态读取不重新启动编码，不进行忙轮询。
- **后续：**研究 LLM 根据结果自主选择补调研、修改假设/方案、再次委派、补实验或报告结束。Codex 的局部编码循环与研究 Agent 的研究决策分开持久化；工具返回 completed 只表示委派完成，不表示整项研究目标已实现。

不要求用户分别启动研究 Agent 和 Codex，也不要求每次委派重复确认；沿用已经明确的执行目标、资源和目录授权。普通聊天/调研的轻量路径保持原样。

“代码报错”通常进入实现修复；“代码正常但假设未被支持”进入方法分析；“证据不足”进入定向调研；“指标提升但代价超标”进入取舍与方案修订。不能见分数下降就一律重写代码，也不能无限重试直到分数变好。

创新点必须各自有可证伪假设和消融映射。用户要求三个技术创新点时，设计同一方法内三个模块及它们的作用关系，不把三个备选课题冒充三个方法贡献。如果证据只支持较少候选，明确缺口，不凑出已验证“创新”。

## 4. 对现有接口的最小扩展

新增 `research_agent/auto_research.py`，负责状态、决策校验与阶段调度。新增 SQLite `auto_research_runs` 表：id、space_id、conversation_id、parent_message_id、status、stage、goal、authorization、budget、state、created_at、updated_at。goal/authorization/budget/state 使用 JSON；方法、报告和实验仍复用现有不可变版本表，state 保存版本引用，不再复制一套研究档案。

当前步骤及决策事件使用已有持久任务/事件机制。每一步交给现有 worker 作为可恢复任务执行，携带 campaign_id 与目标版本；完成后让调度器领取后继步骤，不在单次模型调用中递归跑完整课题。聊天请求仍可受理，普通研究在阶段间排队；长时间训练或编码进程不能长期占用研究 worker。复用现有进程收据与取消机制，新增本机一个实验进程槽，由宿主轮询收据并推进任务，不引入外部队列。按单 GPU 串行运行重计算实验，报告排队时间，不承诺训练满载时聊天/检索延迟不受影响。

拟新增 `/api/spaces/<space>/auto-research` 的创建、列表和详情接口，以及指定 run 的取消/恢复操作；旧会话/实验接口保持兼容。面板展示目标、当前阶段、方法版本、实验矩阵、已核实结果、下一步决定与剩余预算，普通聊天/调研不展示必填实验表单。

研究交接合同保存：目标、实际读过的来源与摘录、方法假设、baseline 仓库/提交/复现结果、数据版本与划分、可编辑范围、预定命令、指标及方向、成功阈值、对比/消融清单、资源预算。`idea_id` 只是归属关联，不能代替以上内容。

将固定 `registered(suite)` 扩展为项目级实验适配合同：在用户授权的项目目录准备代码/数据与环境，宿主锁定评测入口、参数格式、结果文件及哈希；后续方法修改不能同时改评分器或测试标签。Codex 返回代码差异、日志和结果文件，宿主实际执行并核实 exit code、数据划分、配置、代码版本及指标。模型在最终文字中声称的分数不计作结果。

首版支持现有本机 Windows/Codex/Python 环境下的项目任务。新增依赖安装在课题独立环境，下载、数据与权重使用 `D:\paper`，不改用户主环境、.env 或已有 Codex 配置。继续复用现有模型、搜索配置与本机 Codex，无需新账户、MCP 或服务；真实实现前检查现有服务可达性与资源，本轮只查询了公开 GitHub 源码，未进行付费模型连通探测。

主要涉及 auto_research、workbench、store、experiments、process、research_records、server、前端与对应 tests，预计超过 8 个文件；先保持一种本机执行方式，不同时做分布式训练或多种 Coding Agent 适配。

## 5. 可选的整体研究贡献对照

以下是后续需要量化整体研究编排收益时的备选评测设计，不要求为了接入 Codex CLI 先完成它。优先完成 agent-as-tool 与真实研究闭环；现有检索、记忆及上下文评测继续沿用各自有效口径。

采用三组，相同 Codex CLI、底层编码模型、模型参数、任务、初始代码/数据/原始资料访问范围、硬件和总资源上限。冻结自研控制器代码后再跑；每组从干净任务状态开始，不共享其他组生成的方案或实验结果。

| 组 | 输入与行为 | 比较目的 |
| --- | --- | --- |
| A：Codex 直接完成 | 给目标、原始论文/代码/数据和预算，允许自主阅读、规划、运行及基于日志继续修改；不加自研研究控制器 | 一个有能力的直接 Coding Agent 基线，不人为限制为单次输出 |
| B：一次研究交接 | 研究 Agent 调研并形成有依据的方法/实验计划，交给同一个 Codex；Codex 可依据执行日志修复，但研究 Agent 不按结果重新调研/修订 | B−A 衡量初始研究与方案组织带来的整体增益 |
| C：完整研究闭环 | 与 B 相同的初始流程，再由研究 Agent 读取实测结果、补调研、修订假设和实验计划 | C−B 衡量研究反馈循环的增益；C−A 衡量完整系统收益 |

主比较使用同一冻结原始来源池，三个组均可读取全部原文、代码和公开资料，研究 Agent 检索也限定在该池中，不仅给 C 增加关键论文。开放网络的“最新论文发现”另做真实产品演示与来源核验，不与固定来源池的配对结果混为因果对照。资料准备方法、来源截止时间和筛选规则随任务发布，不能看结果后补有利来源。

主实验按相同总资源上限比较，计入调研、规划、编码、核验、反馈的全部模型用量，以及实验计算和端到端时间。A 可以将自己的预算用于更多编码或阅读，不能让 C 免费多用一个研究模型。研究侧与编码侧优先使用同一底层模型以减少模型差异；若换模型，重新独立分组，不能把模型升级收益归入 Harness。记录实际消耗和字段覆盖，未知计量不写成零；token、GPU 时间和墙钟时间分别展示，不伪造统一费用。

可以另加一项只比较反馈决策的诊断：给各方案相同的真实实验日志、代码、证据及剩余预算，比较下一步选择。这项不能代替完整研究任务成绩。

## 6. 指标定义

| 指标 | 计算与判定 | 体现的研究 Agent 作用 |
| --- | --- | --- |
| 研究目标达成率（主指标） | 在固定总预算内，达到事先冻结的任务指标与成本约束、完成必需对比/消融且结果可复验的任务尝试数 / 全部尝试数 | 调研、规划、实验选择和反馈是否提高成功概率；报告 C−A、C−B 的百分点差 |
| 实验决策正确率 | 在冻结日志案例中，选择预先标注的可接受动作并指出相符证据的案例数 / 全部案例数 | 是否能区分实现故障、无效假设、缺证据、成本超标和应当停止 |
| 必需实验有效完成率 | 完成且通过协议/产物核对的必需实验单元数 / 预先冻结的必需单元数 | 是否组织并完成基线、对比、消融，而非只跑最有利一组 |
| 达标所需实验次数与资源 | 从开始到首次开发达标的真实实验数、全部模型 token、计算和墙钟时间；终验单列 | 是否减少无效试错；未达标任务记录预算耗尽，不从均值中消失 |
| 基线复现成功率 | 在预定容差和同条件下复现成功的任务数 / 要求复现的任务数 | baseline 选型、环境与实验条件是否可靠 |
| 结论证据充分率 | 核心结论中同时有相符原文或实验产物支持的项数 / 全部核心结论数；漏答另计 | 研究报告是否把实测发现、假设与猜测区分清楚 |
| 非自动研究请求误启动率 | 聊天、单次调研、头脑风暴等不含执行授权的请求中，实际创建运行实验/调用 Codex 的请求数 / 此类请求数 | Auto Research 是否干扰日常能力；发布门槛为本套件中 0 次误启动 |

“流程完成率”另报，包含正确交付负结果、预算停止和受阻说明；不能混入研究目标达成率。否定一个无效假设可能是正确研究决定，不因此把决策判错；同时不得把它计为预定性能目标已经实现。

主指标不使用 LLM 自评“论文够不够 CVPR”。每个任务预先定义公开评测器、数据划分、主指标、约束指标、容差和必需实验清单，由宿主计分。诊断动作允许多个合理答案，由固定案例标准和独立复核判断；无法建立明确标准的案例单列，不给自由发挥的 LLM 裁判决定主成绩。定量达标也不自动证明论文新颖性或能录用。

## 7. 功能验收与可选评测规模

复用 `datasets/` 管理公开来源与真实项目任务，`tests/` 管理工程测试，`evals/` 放运行器与报告。新增 `datasets/auto_research/`，保存任务清单、原始来源元数据、固定划分与预算协议；评分标签和终验资料仅宿主可读。每个来源记录原始 ID、版本/提交、许可和派生方式，不把派生课题称为官方榜单成绩。

近期功能验收先证明：研究 LLM 在真实 Auto Research 中根据证据形成方案并主动调用 Coding Agent，实际结果正确返回且指导后续研究动作；普通聊天和单次调研不误调用；失败、取消和恢复可查。保存一个实际交付案例及一个需要修订或受阻的案例，不要求必须胜过直接 Codex 或取得 SOTA。

若以后安排完整配对，可考虑 6 个课题 × A/B/C 三组 × 3 次独立重复，共 54 次研究尝试；此规模不是当前必做项或付费运行指令。6 个课题可来自 3 类实际研究问题，每类 2 个：有证据的多文档 Agent 问答、跨会话记忆使用、长任务工具/上下文策略；优先采用已有 QASPER、HotpotQA、LongMemEval 公开子集的适用部分，加真实项目失败任务。开发、终验按论文/会话/任务来源分离；原 V4 排序任务只作执行兼容回归，不当作这 6 个完整研究课题。

这只是规模和取样规则，尚未选出并冻结 6 个课题，也没有新成绩。正式运行前生成完整任务清单，逐项验证公开评分器/许可、可复现基线、资源可行性及目标阈值；选题只依据这些条件，不依据 C 是否获胜。若某类无法在本机预算内运行，保留排除原因并在冻结前调整，不将半成品当研究成功。

产品入口回归采用 24 条用例：6 聊天、8 单次调研、4 头脑风暴/方案设计、2 含糊的论文愿望、4 明确 Auto Research。检查实际创建的任务、Codex 调用和停止点，不能只看路由字符串。未来若量化反馈决策，可采用 24 份真实归档结果，覆盖实现错误、指标退化、成本超限、缺失消融、证据不足、正常达标各 4 份；若使用人为注入故障，单列，不冒充真实模型失败。该专项不阻塞工具与研究闭环交付。

完整任务保留所有首次失败、负结果和重复实验；公布每课题与每重复结果，不把 54 次尝试说成 54 个独立研究方向。不要求所有候选有提升才结束评测，也不追加轮次直到正分。

## 8. 分步交付与验证

1. **入口与研究方案。** 修复已知多工具协议/可见引用缺陷以复用稳定研究基础；增加可选 Auto Research 的目标、预算和方案档案，完成 24 条入口用例。用户可以正常聊天、调研、头脑风暴，也可保存/导出研究方案；未执行的方案明确标为未执行。此阶段独立可用。
2. **Coding Agent 作为工具与完整执行链。** 将已有 CLI 执行器封装成研究 LLM 可调用的持久工具，接通方案版本、baseline 复现、实现、对比/消融与结果回传。先验收一个适合本机的真实课题；即便下一阶段不做，用户也可用研究 Agent 组织一次完整实验。保存负结果或失败案例，不以排序脚本跑通替代整链验收。
3. **研究反馈循环。** 把实测结果传回研究 LLM，验证其根据证据自主决定补调研/方法修订、再次委派或结束；实现预算、取消/恢复、停止原因及最终报告。完成真实闭环即可形成可演示的功能成果和相应简历描述；整体收益对照按需要另行安排，不因缺少 Codex 接入专属量化指标而阻塞交付。

工程检查覆盖：普通模式零误启动；目标/计划/结果版本一致；独立会话及分支边界；非零退出、测量不完整和指标不可比；原文不可达；baseline 不能复现；测试标签不进入规划；评分器不可随候选修改；结果劣化保留最佳；中断恢复不重复已完成调用；预算用尽；进程树取消；正常达标；负结果正确结束。执行 ` .\.venv-v3\Scripts\python.exe -B -m unittest discover -s tests` 和 `node --test tests/test_workbench_frontend.cjs`，再做真实界面和课题验收。配置完整的实际任务才进行付费模型执行，不以 mocked 测试替代真实验收。

所有研究迭代使用开发/验证数据；冻结候选后终验，不把终验逐题错误传回调参循环。要在终验后继续研究，另建研究版本并声明原终验数据已参与开发，换独立确认集。SOTA 参照必须记录时间、来源、数据与资源条件；同条件不成立就报告不可比。预算、用户取消和外部阻塞都是合法结束状态，不能承诺无限迭代必得 SOTA。

## 9. 风险与回退

关键工程假设是：研究 LLM 能把证据转成可执行委派，并正确利用返回结果。若工具频繁缺输入或过早调用，针对实际失败改善方案结构与反馈提示，不以固定流水线假装自主研究，也不把全部任务交给 Codex 后省略研究决策。后续若测量 C−A，没有改善也保留负结果，不能降低 A 的能力或偷加 C 的资源；这不否定编码工具作为必要功能的价值。

保留 SQLite 增量表、旧入口及兼容合同；新控制器可停止调度并回退代码，已有论文、会话、报告和实验版本不回滚。取消清理相应实验进程树，保留工件；模型服务故障保存已完成工作并受限重试，未知计费请求不重放。长期训练不可用或资源不足时返回受阻及已获得证据，不改写为科研目标完成。

旧路线“不要重复已完成 V4”只适用于已完成的执行基础；它与本轮明确的完整 Auto Research 目标存在范围冲突。解决方式是复用执行基础、补研究外层闭环，旧阶段完成记录保留，但不再作为整个 V4 完成的依据。

## 测量、摘要与复验契约

- `protected_files` 对应跨轮永久冻结的数据/评分器；测量期间临时冻结的算法源码在下一轮可编辑，历史删除或重命名文件不会被重新创建。显式保护的文件仍必须存在且哈希一致。
- 宿主测量按任务和命令序号归档 `ranking_file`、`ranking_path`、`predictions_path` 原文及 SHA-256。独立复验使用测量快照；已声明快照缺失或哈希不符即失败。只有历史收据没有快照字段时才允许明确标记 `legacy_workspace` 的兼容读取。
- QASPER 固定合同按 gold 段落比例计算 Recall@5，另报 Hit@5；输入哈希固定，seed 为 1–64 个不重复整数，评分单遍分组。原脚本值保留，畸形输出不会丢弃执行收据。
- `assess_results` 可以在缺测量时调用，但辅助评估不覆盖最终已测方案。验收分别检查完整宿主收据和模型实际可见的候选指标，兼容上下文压缩；达标/改善的决定性配对优先进入摘要。
- 工程路径、指标重算、标准基线正确性和科学有效性分别判断。研究方法必须对照原文或明确版本的参考实现；同一数据集的指标复算一致不能证明算法公式、新颖性或泛化收益。
