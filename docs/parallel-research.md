# 有限 Multi-Agent 并行调研

Auto Research 的主控 LLM 可以调用 `research_parallel`，把两个相互独立的问题交给两个研究 Agent。每个子 Agent 使用自己的模型会话、工具循环、证据和执行检查点；主控等两项结束后读取分项报告，结合失败信息决定继续调研、保存方案、委派 Codex 或结束。依赖上一项结果的问题仍用 `research` 顺序执行。

这是一层主控加两个研究 Agent 的协作。Codex CLI 继续作为可委派的编码 Agent，由宿主运行实验并返回指标。两个研究线程复用现有 SQLite 队列、检索、记忆与资料库，没有引入新框架或图数据库；编码及实验执行沿用原有串行执行器。

## 使用方式

在 Auto Research 目标中提出两个独立研究方向，例如“分别调研论文的核心方法和评测数据，汇总后设计实验”。模型根据问题依赖和剩余预算选择顺序或双路研究。每批恰好两个问题，各占一次研究预算；预算不足时整批拒绝，不留下半批任务。

普通聊天、单次论文调研和资料问答保持已有入口。研究区仍共享资料、Notes 和设置；研究区内会话独立，仅显式历史分支继承历史。并行子任务使用父任务开始前的历史边界，并按自己的研究深度压缩上下文；主控接收两项结果时，每个证据编号同时绑定其子任务，避免混淆不同报告中的 E1。

## 停止、失败和恢复

- 同一工具调用重复提交会复用原来的两个子任务，不重复扣预算或创建任务。
- 两个子任务都结束后才唤醒主控；一路失败不会被当作整批成功，返回中保留各路状态和错误。
- 取消父任务时，在同一 SQLite 事务中取消其仍活动的子研究。已发出的网络请求返回后停止，不再进入下一步；完整请求收据继续保留。
- 忘记历史或修改记忆导致上下文失效后，旧子任务不能继续使用已失效的上下文。服务重启仍按已有规则标为中断，由检查点显式恢复。
- 同一会话的后续用户轮次不能越过尚未结束的父研究。共享论文分析使用实例锁，避免两路同时分析同一篇资料时覆盖结果。

## 验收与指标口径

冻结面板为 `datasets/project/parallel-research-v1.json`，复用四道已有项目问题及公开论文、源码文档原文，分为两组，每组两次重复。单 worker 与双 worker 都运行真实 Workbench、研究主控和 Luna 子 Agent，使用相同资料、工具、问题与预算；仅调度槽数量不同。两种配置交替先后运行，共 8 个父任务、16 个子研究。

复现命令：

```powershell
.venv-v3\Scripts\python.exe -B -X utf8 evals/run_parallel_research_acceptance.py --output evals/reports/parallel-research-live-<new-run>
```

报告记录交付耗时、两路实际执行重叠、任务完成率、原文阅读与引用覆盖、逐事实人工复核及全部模型费用。所有首次运行和失败保留；成功配对的时间比较单列，不能掩盖失败。该面板检验本项目的并行调研，不是官方 benchmark 成绩，也不据此宣称一般研究质量提升。[首次真实验收](../evals/reports/parallel-research-final-audit-20261003/report.md)已完成：16个子研究交付，4次并行均有真实重叠；严格任务合同6/8通过，两次“不联网”转交遗漏仍由LOCAL_QA宿主边界约束。14份精确匹配答案的32项预设事实均有已读原文和引用支持，逐项审阅见报告。四组配对合计双worker慢8.33%，不能宣称总体加速；完整失败和费用归档，不追加试验追分。
