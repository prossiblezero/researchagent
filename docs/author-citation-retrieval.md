# 作者消歧、作者作品发现与引用关系检索

当前 Agentic RAG 增加两个工具：`lookup_papers` 查询研究区内论文的作者与引用关系，`discover_author_papers` 从已保存论文的 DOI 定位 OpenAlex 作者记录，再分页查找其他作品。模型取得关系线索后，继续调用现有 `read` / `read_evidence` 阅读原文和核验答案。

可以询问：“这几篇论文是否属于同一个作者团队？”“两篇论文共同引用了哪篇工作？”“沿这篇论文的作者查找其他相关论文，再比较它们的方法。”

## 本地关系工具

| `lookup_papers.mode` | 用途 | 输入 |
| --- | --- | --- |
| `authors` | 查看论文署名及原文位置，保留署名顺序 | 可选 `artifact_ids`、`author`、`query` |
| `author_papers` | 找到同全名论文候选，并与种子作者比较身份线索 | `author`；可选一个种子 `artifact_ids` |
| `references` | 查找指定论文引用的已保存论文 | `artifact_ids` |
| `cited_by` | 查找哪些已保存论文引用了指定论文 | `artifact_ids` |
| `shared_references` | 求所有指定论文共同引用的已保存论文 | 至少两个不同 `artifact_ids` |

论文 ID 沿用 `retrieve` 返回的 `owner_id`。结果分页返回 `total` 和 `next_offset`，并提供原文 `ref_id`、页码、章节；引用关系给出来源论文和目标论文，跨段题名保留两段位置。查询结果是阅读线索，答案中的事实仍须绑定实际读取的原文 E 编号。

作者优先从首页摘要之前的清晰署名行提取，补全 PDF `/Author` 缺失、只有首位作者或误填出版商的情况；元数据中的姓名仍须能在原文署名区域找到。保留原文顺序和定位，元数据中的 ORCID 只与同名原文署名结合。标题、机构、邮箱和参考文献中的人名不能单独充当署名。当前自动恢复针对可解析的拉丁字母多人署名行；扫描件、歧义排版及未识别姓名会如实保留缺口。逗号或分号连接的完整署名会拆分，`Wang, Z.` 等缩写不会自动展开成某个全名。

同名记录保留为每篇论文上的独立署名，不自动合并。消歧结果包括：

- `seed_record`：种子论文本身。
- `shared_orcid` / `conflicting_orcid`：元数据中完整 ORCID 相同或冲突。
- `shared_name_and_email`：相同全名，原文中存在可按完整姓名对应的相同邮箱。
- `unresolved_same_name`：只有同名或背景线索，身份仍待核实。

机构与合作者作为补充线索返回。`paper_affiliations` 是论文首页的机构列表，不表示每个作者都属于列表中的每个机构，也不能证明师生关系、团队正式成员身份或个人贡献。

引用索引在识别出的参考文献章节中匹配已保存论文的 DOI 或完整题名，检查题名起止边界，保留方向和原文；不把较长题名的前缀或后缀识别为另一篇论文。自动题名索引仍采用最小长度门槛，歧义排版保留未识别状态。题名匹配可能涉及匿名稿、预印本与正式版，须继续核对年份和版本；共同引用或明确引用均不能单独证明方法继承、代码复用。没有入库的目标论文、无法识别的参考文献和简称不在当前边集内，因此缺边不能作为“没有引用”的证据。

## 从种子 DOI 发现作者其他作品

`discover_author_papers(seed_artifact_id, author, author_id?, query?, page?, per_page?)` 只在允许联网的研究任务中提供。本地问答不会暴露或执行它；两个新增工具均在当前研究区存在可读论文时才进入工具清单，避免占用无关任务的上下文。

流程如下：

1. 确认种子属于当前研究区、原文可读，指定全名出现在种子署名中。
2. 用种子 DOI 查询 OpenAlex 的作品记录，校验返回 DOI 一致。
3. 在该作品的署名中寻找完整姓名相符的作者 ID；有多个候选时返回候选供模型继续核实，不按名字全局选中某人。
4. 按选定作者 ID 和可选主题词查询作品，返回候选署名、机构、年份、来源链接及分页信息。传入的作者 ID 必须属于前述种子的候选。
5. 候选公开链接进入既有来源目录，Agent 可以沿链接读取出版页面或 PDF，核对身份与发表版本。候选记录不会自动成为已验证作者关系，也不会自动导入资料库。

候选同时返回最佳开放版本、出版版本及其他公开位置，PDF 优先，保留提供方的版本标签与共同作者线索。排除种子 DOI 本身；同篇其他版本仍须去重。用户限定研究领域时，提示 Agent 使用主题过滤，并先读候选，再扩展搜索。备用地址只来自实际返回的公开位置，不拼接下载地址。

Agent 从已有工具记录重建候选读取进度：已读原文编号、失败地址/错误和下一可读地址。该状态随既有断点记录保存，在上下文压缩后仍可见；“已读”不表示作者归属、版本或引用关系已核验。模型需逐篇核对这些事实。拦截页、验证码页与空正文不会成为原文证据，也不会存成可读资料。获取失败时，优先尝试同篇备用地址，再按准确题名找公开原文或沿种子参考文献查找；不能拿摘要补作核验结果。

启用答案核验且已得到联网论文候选时，首次成稿最多预留 3 次工具尝试供核验后的补读（小预算按四分之一取整，包含在原总预算内）。修订提示从已有原文按缺项重新提取最多 6000 字符，保留 E 编号、证据角色和原文位置；摘要不会混入。仅兼容去除误回显的 `type: json_object` 字段，未知字段和伪工具参数仍拒绝。所有合并后的段落补丁继续经过事实/需求核验，已核验事实段落仍锁定。原文不可得时保留有依据的部分和明确缺口，不宣称完成四篇核验。

用户按完整题名点名的可读本地论文也保留独立的读取清单，跨上下文压缩和答案修订更新；删除摘要引用不会删除待阅论文。多篇本地论文同样预留修订工具预算。核验模型先依据完整问题返回 `required_document_ids`，明确回答所需的原文范围；发现该范围内未读原文或缺少引用方参考文献时，在剩余预算内经原有工具执行、权限检查和断点保存流程安排 `read_evidence(document=true)`。仍有具体可补读位置时不接受“没有原文”的终止理由；预算耗尽或文件确实不可读时继续保留未完成状态。位置清单中的 `mentioned` 只表示标题被提及，不代表授权或必读要求；选源范围由核验模型根据完整问题语义给出，不靠有限关键词推断。范围字段缺失或 ID 不属于本次清单时走格式纠正，不能默认选择全部论文。选择是否符合问题仍依赖模型语义判断，不是通用权限正确性保证；网络、文件可见性及跨研究区权限仍由宿主校验。已读片段不等于整篇读完，也不自动证明作者身份或需求已覆盖。

重复动作使探索停止后，核验发现具体缺口时可以在原剩余预算内恢复修订工具；已经执行过的补读不会被再次自动排队。核验输入保留点名论文已读首页及引用条目，防止宽泛的关键词排序挤掉机构、邮箱、发表和版本证据；模型返回的修订候选 E 编号必须映射到真实已读原文，且只用于修订提示，不替旧段落补授事实支持。

论文引用断言另提取引用方和被引方，结合原文参考文献索引检查方向与本段绑定的证据。字面箭头额外作确定性检查，因此总结中的 `A↔B` 不能靠单向 `A→B` 的依据通过；修订后也重新检查。缺少参考文献阅读时补读，已读但引用漏绑时提示正确 E 编号。关系线索只用于核验和定位，不会直接变为答案证据；尚未识别到的边仍不能用来证明不存在。若索引缺边但引用原文已读，核验器可在关系对象中提供 `evidence_id` 与逐字 `quote`；程序要求该证据绑定本段、属于引用方、含目标完整题名且原文中的题名边界成立；跨段可用 `evidence_ids` 指定同一引用方的相邻原文块，程序按解析器的 `ordinal` 检查顺序，禁止跨来源、跳段或拼接未绑定证据。语义核验仍须判断是否为明确引用。缺失必填的 `citation_relations` 数组触发一次格式纠正，不按空关系放行。自然语言关系抽取、未识别别名和原文解析仍有覆盖局限，此机制不是完整知识图谱或通用推理正确性保证。

模型 HTTP 响应体中途截断（`IncompleteRead`）沿用既有重试次数与任务时间限制，失败尝试独立记账。可选的语义压缩在客户端传输重试耗尽后直接退回本地有界压缩，本轮不继续叠加语义压缩重试。修订阶段发生模型、输入预算或时间中断时，交付已核验部分与未完成项，并保留原有断点；整体任务仍标为未完成，不把部分交付改算核验成功。

响应截断最终失败会归一化为模型异常，保证核验阶段进入“保存待核验草稿”分支。DSML/XML 工具调用标记不能作为最终答案或核验草稿：只给一次成稿纠正机会，仍失败则明确未完成；不执行标记中的工具。旧断点中误存的同类伪草稿也会清除，已读证据继续保留。

启用答案核验时，进入仅成稿阶段会从证据目录重建有界的原文输入，不再把旧 assistant/tool 调用历史交给模型续写；保留原文 E 编号、证据角色与出处，未读摘要不混入。这样在预留工具供核验补读时也能明确切换到成稿。生成的答案仍经过原有核验与修订，不执行任何混入正文的调用标记，也不增加总工具预算。

核验合同版本改变时，旧判定与待执行补读队列一同失效，已读证据与已用预算保留并重新核验。从此类失败断点续跑时，旧的非法调用文本不会再次作为待执行成稿重放；在原迭代位置发起一次新的成稿请求，继续复用证据与已用工具计数。若新的请求仍返回非法标记，仍保留失败状态，不把格式恢复等同于事实通过。

局部修订也使用独立上下文：已核验且锁定的段落、可编辑段落、核验缺口、当前相关原文和真实工具权限。保留最近两组经压缩的完整工具交互及候选读取进度，使新检索位置、错误和分页信息能进入下一轮决策；更早的调用历史不重复携入。作者关系结果保留原文定位、身份线索及当前页全部结果，不在分页字段声称结束时隐去页内记录。检索预览仅作线索，不能成为事实依据。证据目录只保留有效编号与角色，标题和出处放在实际引用的原文摘录中。新增读取仍进入同一证据目录并参加后续核验，避免大量段落反复携带长论文题名造成受保护上下文溢出。

OpenAlex 作者 ID 可能存在拆分或错误合并，作者作品列表也可能不完整。返回的 `identity_check` 区分需要原文核验的 ID 匹配与作者名字冲突。API 失败会记录已发生的请求并返回可继续使用普通 `search/read` 的提示，不将服务失败解释为作者没有其他作品。

公开接口沿用现有有界下载和公网地址检查，不引入新服务、依赖或配置项。作者发现与后续读取计入原有工具及网络调用记录。无 `.pdf` 后缀但实际返回 `application/pdf` 的出版方下载链接会转入已有 PDF 解析器，原始读取和后续下载均计数。

“明确／直接／方法／代码／问题继承”等肯定断言还必须绑定本段所引原文的逐字摘录，由核验模型检查是否明确支持基于、扩展或复用。程序校验摘录确实存在于所引证据；没有该依据时拒绝把引用、基线对比或共享问题写成继承，并要求修订为“明确引用”或“共享研究问题”。否定或无法确定继承不要求额外摘录。自然语言识别仍有边界，这不是对任意继承断言的形式证明。

## 存储与验证

SQLite 增量添加 `paper_relation_state`、`paper_authorships`、`paper_citation_edges`。这些表是可重建索引：源资料、元数据、可见性或内容改变时重新生成；原文与已有人工关系记录不被修改。索引只含当前研究区可读取的 `paper`，不将 Agent 历史报告抽成论文事实，不跨研究区查询。

实现位于 [paper_relations.py](../research_agent/paper_relations.py)，通过 [retrieval.py](../research_agent/retrieval.py) 接入 [Agent 循环](../research_agent/loop.py)。针对性验证：

```bash
python -m unittest discover -s tests -p test_paper_relations.py -v
python -m unittest discover -s tests -p test_discovery_recovery.py -v
```

真实语料、同题复测、评分和 GraphRAG 决策记录见 作者关系检索评估（本地档案：`research-notes/author-relations-20261010/report.md`）。该评估继续区分关系索引是否找对、模型答案是否完整、引用是否充分和产品是否成功交付。只有剩余失败集中在大规模主题覆盖或跨社区归纳，并且现有关系扩展与原文阅读不足时，才进一步比较社区摘要等能力。

原文获取与交付修复的独立复测见 联网恢复评估（本地档案：`research-notes/discovery-recovery-20261010/report.md`）。它只复测种子拓展和此前两个归纳失败案例，不替换原十题成绩，也不作为独立泛化测评。

人工补充三份原文后的五篇论文任务已完成四篇候选核验、引用方向检查和局部修订交付，见 最终交付实测（本地档案：`research-notes/manual-paper-final-20261010/report.md`） 与 带原文定位的实际答案（本地档案：`research-notes/manual-paper-final-20261010/answer-with-sources.md`）。新建完整任务通过后，最终源码对同一答案所有段落重新核验通过；生成阶段与最终核验的源码差异、实际失败和可选记忆抽取错误均保留。4/4 只是一题的候选覆盖。十题同题复测已有独立记录：严格完成6/10→8/10（60%→80%），成功交付8/10→10/10（80%→100%），见作者关系检索评估（本地档案：`research-notes/author-relations-20261010/report.md`）；本次人工原文任务不用于进一步上调十题成绩。
