# 记忆、流程技能与经验学习

ResearchAgent 现在把可追溯的知识条目与可调用的操作流程分开保存。模型权重保持不变；经验通过提炼、独立验证和版本更新影响后续任务。

## 如何使用

打开工作台的“策略改进与反馈”，下方是“学到的流程”。可以查看步骤、适用/排除条件、来源任务、版本及验证结果，暂停、恢复、回退或导出标准 `SKILL.md` ZIP。导出不安装到全局目录，不包含原始私人轨迹。候选必须经可信本地评测才能启用，HTTP 不接收模型自报的成功率或 `passed` 值。

项目内置三个人工整理的种子流程：原文定位与引用修复、跨论文比较、实验条件与负结果解释。前两项供研究执行器使用，第三项供具有 `inspect` / `assess_results` 工具的 Auto Research 控制器使用。种子是可检查的工作指南，尚不代表实测收益。

已结束任务可从面板选择“提炼流程”，也可以在该会话发送“把这次流程记为技能”。该请求形成待验证候选，不能直接绕过准入门槛。

后台学习默认是 **只整理候选**：有至少 6 次实际工具调用并具备可核验的成功/局部恢复信号时登记轨迹，累计 3 个同类独立父任务再归纳。重试和同一 Auto Research 的子任务不重复算独立支持。显式提炼请求可跳过次数和积累门槛，但仍需真实支持。

每批提炼最多 2 次模型请求、16,000 总 token 预留和 180 秒，单请求输出最多 4,096 token（含推理）。允许不产生候选；同一活动基线最多初稿加两次修订。前台任务优先，后台整理中断后保留收据，不偷偷重复未知调用。

“只整理候选”也可能调用已配置的模型；验证额度为 0 只会阻止自动资格验证。需要停止自动提炼时关闭后台学习。

“验证通过后自动启用”需要在面板分配有限的剩余验证额度。一次固定资格验证最多预留 1,152,000 token（36 个情景 × 有/无技能 × 每次 16,000）；仅实际请求产生模型费用，确定未使用的预留额度会返还，未知消耗保持预留。默认验证额度为 0，不会自动启动付费评测。

## 运行行为

- 初始研究知识按当前问题用已有 FTS/BGE 混合召回，继续应用会话/分支、状态和时间过滤。明确偏好优先，初始记忆预算仍为 `min(1024, 输入预算 × 5%)`。没有相关命中就不塞入无关结论。
- finding 可带 `conditions`、`concepts`、`observed_at`、`valid_from`、`valid_to`；它们与正文一起接受原文支持检查。无法确认的日期留空。修改正文会清掉旧 metadata，旧记录不批量重写。
- 原文、工具轨迹和证据仍保存。抽象记忆不代替原始证据，也不关闭原文直接搜索。`memory_selection` 收据记录候选、送达、预算落选及内容哈希。
- `skill` 工具仅提供 search / load。目录最多 3 项、约 240 估计 token；正文至多约 800 token。一个任务最多加载一个主流程和一个局部恢复流程，消耗现有工具及上下文预算。恢复流程还受两次后续工具动作上限约束。
- 运行开始时固定技能版本、模型和工具合同；恢复沿用原版本。新版本只影响后续任务。加载原因和后续工具行为写入 Trace/事件，不能仅凭“加载过”宣称执行了所有步骤。
- 暂停/回退影响之后的任务；遗忘或来源撤回会阻止相关内容继续使用。遗忘保留来源标记，改名也不能从同一来源重新生成。
- 文本流程不会增加工具权限、执行生成脚本或改写项目源码。源文件、引用和实验测量继续由原来的代码合同核验。

## 验证与证据边界

`datasets/project/experience-learning-v1.json` 固定 18 个合成来源组，开发、验证、最终测试各 6 组；每组包含知识、流程迁移、恢复与不适用控制，共 72 个情景。不同切分不共享来源组，但共享任务类型，不能据此声称广泛科研能力或论文级新颖性。

最终比较保留四臂：原先的初始知识选择、相关性知识选择、相关性知识加总是加载匹配技能、相关性知识加按需加载。每臂都能回查相同原文。所有运行在独立 SQLite 与报告目录内，不读取默认用户数据库，不重跑已经结束的 A-MEM 留出实验。

晋升至少需要 24 个相关任务、12 个不适用控制，以及两个来源组；报告按来源组聚类的配对区间。模型、源码、来源、索引、历史、预算、工具及技能哈希均固定。引用支持率不得降低，不适用控制不得新增错误或技能加载；相关任务成功率需提高至少 5 个百分点且平均 token/P95 延迟均不超过 1.2 倍。成本优先路径还要求计入构建摊销后的完整费用，不能拿执行侧节省冒充总成本节省。

当前自带的自动资格验证覆盖本地原文研究工具合同；涉及联网、代码执行、实验控制器或其他工具的生成技能保留为候选，标记验证覆盖不足。不会拿本地阅读结果外推到 Auto Research 的其他能力。人工种子仍可按其实际工具要求使用。

离线客户端使用固定动作与可核查的逐字引用核验，只验证工程接线和数据合同，所有计量明确标记为估算。**离线结果不能晋升生成技能，也不能证明真实模型收益。** 真实模型评测只在显式给定 CLI 预算或研究区已有自动验证额度时运行。

```powershell
.\.venv-v3\Scripts\python.exe -B -m unittest discover -s tests -p test_skills.py -v
.\.venv-v3\Scripts\python.exe -B evals/run_all.py
node --test tests/test_workbench_frontend.cjs
.\.venv-v3\Scripts\python.exe -B evals/run_experience_learning.py --stage dev --offline --output evals/reports/experience-learning-new-run
```

评测目录必须是新的目录；首次失败保留。`--stage report --output <已有目录>` 只重建汇总，不调用模型。真实四臂入口去掉 `--offline`，显式指定 `--model` 和至少 1,536,000 的 `--token-budget`，仍按每次运行 16,000 的上限执行。

推理模型的输出额度包含推理 token。CLI 可用 `--output-cap` 和 `--per-run-token-budget` 为所有实验臂统一设置上限；总预留 `--token-budget` 至少为单次额度的 96 倍。例如 `--output-cap 8192 --per-run-token-budget 32000 --token-budget 3072000`。这些设置写入条件指纹，不修改后台资格验证的默认预算。应先确认核验器能在额度内返回完整结果，不能把截断输出当作技能优劣，也不能免掉核验来获得正分。

可用 `--skill-definition <导出包内 references/definition.json>` 固定要比较的生成技能；省略时使用人工比较流程作为基线。评测保存该定义与内容哈希，仍不会访问用户运行库。关闭后台整理时，用户显式发起的单次提炼请求依然可执行。

## 存储与回退

迁移仅增加 `memory_items.metadata`、研究区学习设置和 `skill_versions` / `skill_heads` / `skill_evaluations` / `skill_learning_jobs` 四表。SQLite 是唯一可编辑真源；技能文件是导出物。正文和来源内容版本固定，状态、有效作用域与活动指针属于受控生命周期。

迁移随下次正常启动执行。部署前应使用 SQLite 一致性备份保存运行库；不要用旧数据库覆盖部署后的新会话。关闭后台学习和暂停技能可保留全部历史数据；代码回退不要求删除新增表。向量不可用时继续词法检索，没有新增服务、账户、MCP 或环境变量。

图扩展尚未加入：只有在审阅的 20 个记忆使用失败中至少 5 个确认来自已保存知识之间的关系缺口，才进入单独实验。现有成果图继续承担组织用途。若两个候选修订周期后仍无独立收益，就保留相关性记忆和流程库，停止扩展自进化机制。

## 2026-10-07 优化窗口

一天执行目标、费用上限及回滚源码见 [执行计划](../research-notes/day-optimization-20261007/plan.md)。当前候选缩短研究回答与局部修订输入，保留事实段落与已读原文绑定；有总 token 计量的评测执行器会预留最后一次核验。纯用户文本控制题使用工作台 CHAT 路由，研究题按最终段落核验判定，合理的不确定性说明不会因 claim 状态被误判，实际已读来源的 E/S 引用均可接受。

官方 DeepSeek 的 deepseek-flash / deepseek-pro 在核验、技能提炼及来源检查时使用 low 推理档和 JSON 输出，实际请求选项记入用量收据；其他模型沿用原选项。关闭推理的实验因漏答误判已被淘汰，没有启用。模型核验仍不是形式化证明，低推理档是否改善整体质量与成本必须看真实任务对照。

技能目录在既有 240 token 上限内同时展示触发和排除条件；按需使用仍允许不加载。实际轨迹提炼可产生 rejected / no_change，不能把它们算成已学会的可复用技能。独立公开论文对照使用冻结源码和同一评分器，见 [评测协议](../research-notes/day-optimization-20261007/holdout-protocol.md)。

最终保留版本及各次候选的差异见 [选择记录](../research-notes/day-optimization-20261007/final-selection.json)。低推理核验在有总用量计量时，可使用剩余的 4,096–8,192 输出空间，依然必须返回完整核验结果；满足严格条件的只补引用操作须重新核验，公开对照中没有实际触发或收益证据。动态剩余输入压缩未保留，不能将其工程检查通过当成产品改进。自动资格验证在原 16,000 单项总预算内使用 4,096 输出上限，默认验证额度仍为 0。


## 2026-10-07 继续优化的实际结论

后续优化未提高真实任务完成率，最终上下文投影、自动读取前三段、提前结束及预算重分配候选均已撤回。当前只追加两个局部修复：核验输入过滤与所检原文和回答引用均无关的未读来源目录；模型客户端拒绝执行本次未提供的工具。原文与引用绑定规则不变，未启用生成技能。

后续三批分别为 2/6 → 0/6、0/2 → 0/2、0/1 → 0/1，各批候选和部分预算不同，不能合并。保守预算扣除累计 4,985,815 / 5,000,000 token，其中 27,707 是一次无用量收据请求的上界预留，不能当作供应商实际计费。完整负结果、回退决定及最终补丁见[继续优化报告](../research-notes/day-optimization-20261007/pipeline-report.md)和[最终选择记录](../research-notes/day-optimization-20261007/pipeline-final-selection.json)。工程检查通过不代表任务能力提高。
