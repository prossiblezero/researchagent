# ResearchAgent｜科研调研与自动实验工作台

**技术栈：**Python、JavaScript、FastAPI/SSE、Agent Harness、Agentic RAG、Multi-Agent、SQLite（FTS5）、ChromaDB、BGE-M3、LLM-as-a-Judge、Docker

**项目描述：**针对论文调研中单次检索易漏证据、长资料超出上下文、对比实验依赖人工的问题，独立设计并开发 Agent 工作台（核心代码约 1.6 万行），支持多轮论文检索、跨文档问答、报告生成，以及“调研→方案→编码实验→反馈”的自动研究；配套 700+ 项自动化测试与 Windows/Ubuntu 双平台 CI。

**主要工作：**

1. **意图识别与任务执行：** 用户请求混合聊天、调研、资料问答、编码与自动研究等类型，长任务易因超时或中断而失败。设计结合会话上下文的七类意图路由，构建支持工具参数校验、超时控制与断点续跑的 Agent 执行框架。在 MASSIVE 子集＋自建场景的 **210 题**测试中，意图识别准确率 **93.81%**（经标签复核）；在资料规模超出单次 **16K 上下文**的 **14 题**问答任务中，任务完成率 **85.7%**，同模型直接截取原文的单次 API＋Prompt 为 **35.7%**。

2. **Agentic RAG 与跨文档问答：** 论文问答常需多跳、跨文档推理，单次检索易漏证据、引用难以核对。由 Agent 按需决定检索时机、依据中间证据改写查询，交替执行检索与原文分页阅读，并对回答做段落级引用核验，证据不足时补查或修订；底层融合 **FTS5/BM25 关键词检索与 BGE-M3 向量检索**，以 RRF 排序。在 SciFact 检索子集（**5,183 篇摘要**）上，相比纯 BM25，Recall@5 由 **75.0% 提升至 87.5%**，MRR@5 由 **0.604 提升至 0.714**。

3. **记忆与经验学习：** 长任务易超出上下文、跨会话重复检索，且 Agent 难以复用历史任务中的有效做法。设计会话记录、研究区共享记忆与全局偏好三层记忆，结合历史混合检索与上下文压缩保留任务进度；**受 JitRL 启发**，在模型参数冻结的前提下从任务成败轨迹提炼过程经验，供后续任务按需检索复用。在自建 **20 道后续任务**对照中，相比原始关键词记忆，任务完成率由 **65% 提升至 75%**，平均耗时降低 **7.5%**。

4. **Auto Research 与多 Agent 协作：** 科研中复现基线、对比改进方案需要大量人工编码与实验。设计“文献调研→方案生成→编码实验→结果反馈”的自动研究闭环：主控 Agent 分解任务，协调研究 Agent 与编码 Agent，自动运行基线、候选及消融实验；实验由宿主独立执行并评分后回传，编码 Agent 的自述不计为成绩。自动生成的候选方案在 **SciFact 开发集证据分类**中将 **macro-F1 由 45.04% 提升至 49.00%**，在 **HotpotQA 64 题证据检索**中将 **Recall@2 由 59.38% 提升至 65.63%**。

5. **四维评测与策略迭代：** Agent 回答难以用单一自动指标衡量，LLM 裁判本身也可能误判。构建覆盖 QASPER、SciFact、HotpotQA、LongMemEval 及项目场景的 **320 条评测任务**，结合确定性检查、**LLM-as-a-Judge** 与原文复核，从事实正确、内容完整、引用支撑和无据添加四个维度评分，并用 **80 条受控样例**校准裁判，准确率 **92.5%**。据失败归因迭代多工具响应处理、引用绑定与核验修订策略，同一 **24 题**严格任务完成率由 **25.0% 提升至 75.0%**，多工具协议失败由 **14/24 降至 0/24**。
