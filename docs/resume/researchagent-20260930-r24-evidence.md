# r24 简历证据与面试说明

2026-09-30（北京时间）。r24 根据最新真实 Auto Research 验收重写主条目，保留 r23 及更早版本和原始报告。文案把“功能路径通过”和“科学效果验证”分开；Codex 只作为可调用编码工具，不能把其编码能力写成研究 Agent 收益。

## 我理解的项目目标

项目最终要成为一个按需进入 Auto Research 的研究 Agent，而不是把每次普通问答都升级成自动科研。

普通聊天、论文调研和资料问答时，系统应快速检索、阅读、总结和引用；研究区共享资料、Notes 和设置，区内允许多个独立会话，只有用户显式从历史消息分支时才继承该段历史。

用户明确给出复杂研究目标后，系统才进入完整循环：

```text
目标拆解
→ 检索最新论文/报告并读取原文
→ 建立 Claim–Evidence–Source
→ 总结方法、输入输出、数据集和代码状态
→ 找研究缺口，提出仍属于 HYPOTHESIS 的创新候选
→ 选择 baseline，设计对比实验和消融实验
→ 研究 LLM 按需调用 Codex 实现
→ 宿主独立执行、测量并回传真实指标
→ 根据指标继续调研、改方案、重跑或结束
→ 生成可追溯报告
```

项目本身的价值在证据约束、研究状态、工具编排、实验条件比较、反馈决策、恢复和可查交付；Codex 的编码能力属于外部工具能力。

## 最新 Auto Research 证据

- R4 功能验收：`evals/reports/auto-research-live-20260930-luna-r4-comparable-seed/`。`passed=true`、`functional_path_completed=true`、`model_received_experiment_results=true`；baseline/candidate/ablation 均有有效宿主 measurement。受控 SciFact 结果为 baseline accuracy/macro-F1 **0.4853/0.4504**、candidate **0.5294/0.4900**、ablation **0.5324/0.4849**。candidate 的 macro-F1 高于 baseline，但 accuracy 低于 ablation，因此没有包装成整体科学改进；`scientific_effect_verified=false`。
- 强制反馈迭代：`evals/reports/auto-research-live-20260930-luna-iteration-r1/`。`passed=true`、`functional_path_completed=true`、`feedback_iteration_path_completed=true`、`plan_versions=2`。首轮 candidate macro-F1 **0.484150**、CONTRADICT F1 **0.105263**；研究模型识别弱项并保存 v2 方案，修订重跑 macro-F1 **0.491661**、CONTRADICT F1 **0.120690**。`revision_ablation` 当时仍是 baseline proxy，严格新增特征消融尚未完成；因此这组结果证明反馈驱动路径存在，不证明新增特征因果收益。
- 真实失败全部保留：包括首轮输出路径错误、Codex 修复时 Windows 原生 ACL 写保护，以及 `revision_ablation` 不是严格独立变体。失败不会被成功重跑覆盖。

## 可以写在简历和面试里的话

> 我做的是一个按需进入 Auto Research 的证据驱动研究 Agent。普通聊天和调研保持轻量；进入 Auto Research 后，研究模型负责读原文、形成假设、选 baseline 和决定是否调用 Codex，Codex 只负责实现，宿主独立执行和测量，再把真实结果交回研究模型决定继续、修改、重跑或结束。现在已经跑通一次可追溯的反馈迭代路径，并保留指标方向不一致、消融不完整和编码修复失败；下一步是用更多课题、seed 和严格比较验证科学闭环。

## 暂时不能写成已完成

- 完全自主科研、稳定达到 SOTA 或跨课题泛化；
- Codex 的编码分数证明研究 Agent 有效；
- 单次 SciFact 结果证明候选方法已被科学验证；
- 多数据集、多 seed 已证明自动继续/停止决策可靠。
