2026-09-30（北京时间）。本版在 r20 基础上补入 Luna R2 的最终终态：真实结果已经回传给研究 LLM，并形成第二版方案、重新测量和完整失败记录；任务因预算耗尽结束，严格验收仍为 `passed=false`。历史结果、原始报告和失败记录继续保留。

## 我理解的目标

项目最终要成为一个“按需进入 Auto Research 的研究 Agent”，而不是把所有请求都强制变成自动科研。

普通聊天、论文调研和资料问答时，用户只想了解一个领域或几篇论文，系统应直接检索、阅读、总结、回答和引用。研究区共享资料、Notes、设置和历史成果；区内可以有多个相互独立的会话，只有用户明确从历史消息分支时才继承该段聊天历史。

用户明确给出复杂研究目标后，系统才进入 Auto Research：

```text
目标拆解
→ 检索最新论文/报告并读取原文
→ 建立 Claim–Evidence–Source 关系
→ 总结方法、输入输出、数据集和代码状态
→ 找研究缺口，提出仍属于 HYPOTHESIS 的创新候选
→ 选择 baseline，设计方法、对比实验和消融实验
→ 研究 LLM 决定是否调用 Codex 这个工具实现方案
→ 宿主独立执行代码并测量结果
→ 根据真实指标继续调研、修改方案、重跑，或说明研究结束
```

Codex 的编码能力是外部工具能力。项目本身的价值在于研究状态、原文证据约束、工具编排、实验条件比较、反馈决策、恢复和可查的研究交付。

| Codex 作为工具 | 已接通基础 | 需要更多真实案例证明研究 LLM 能在合适时机调用、复用已有代码并处理失败 |
| 宿主管理实验模型 | 接口和隔离已实现，49/49 回归通过 | 本轮真实模型调用数为 0，尚无基于该接口的新科学结果 |
| 根据结果继续/停止 | 有 baseline/candidate 比较和失败保留 | 尚未在多个真实课题上证明能稳定地根据指标选择继续调研、改方案、重跑或结束 |
| 复杂课题自主科研 | 未完成 | 还缺跨轮计划一致性、多数据集/多 seed、统计比较、结果可信度审计和更强原文核验 |

按用户目标看，项目已经完成“可演示的研究基础设施”和“一次真实反馈迭代的结构路径”；尚未完成“复杂课题的稳定自主科研”。剩余工作集中在闭环可靠性和实证规模，而不是再做一个孤立页面：

1. 用宿主管理模型接口完成至少一例真实模型实验，保留模型收据、请求/响应哈希、实验代码、测量结果和失败记录。
2. 在第二个任务或数据集上复用同一控制器，至少做多 seed 或重复测量，验证研究 LLM 会根据真实反馈选择继续、修改、重跑或停止。
3. 增加跨轮状态检查：方案版本、baseline、数据划分、代码版本、指标方向和证据来源必须保持一致，条件不一致时不得自动宣称改进。
4. 强化“读原文后再提出创新”的验收，记录漏读、引用不足、核验超时和无效候选，不把失败重跑覆盖成成功。

## 可以写在简历上的当前结论

可以写：

> 实现了一个按需进入 Auto Research 的证据驱动研究 Agent：普通聊天/调研保持轻量独立，复杂目标下由研究 LLM 规划检索、原文证据、假设、baseline 与实验，并按需调用 Codex；宿主独立测量并将结果回传，支持方法修订、重跑、报告和实验版本归档。在 SciFact 官方开发集固定 cited-doc 子任务上完成一次真实“结果回传→第二版方案→重跑”，准确率由 0.5235 提到 0.5353，但 macro-F1 和 CONTRADICT F1 下降；预算耗尽、整体门槛未通过，失败和边界均可追溯。

暂时不要写：

- “完成完全自动科研”或“稳定达到 SOTA”；
- “Codex 的编码指标证明研究 Agent 有效”；
- “多数据集、多 seed 已证明自动决策泛化”；
- “候选方法已经验证有效”。
