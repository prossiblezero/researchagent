# ResearchAgent｜证据驱动的科研调研与 Auto Research 工作台

**核心技术：**Python、JavaScript、Agent Harness、Multi-Agent、SQLite、ChromaDB、Docker

**项目描述：**面向论文调研与研究方案验证场景，针对资料分散、原文核验依赖人工、长任务上下文易丢失，以及调研结论与编码实验脱节等问题，独立设计并实现证据驱动的研究 Agent 工作台。以可信 RAG、分层记忆和 Agent Harness 支撑日常问答与深度调研，并通过多 Agent 协作和按需启动的 Auto Research，串联文献分析、方案设计、编码实验与结果反馈，使研究过程可追溯、可恢复、可复用。

**核心职责与贡献：**

1. **Agent Harness 与任务恢复：**围绕长链路任务中的工具调用失败和中断后状态丢失，构建意图路由、工具校验、预算控制、Checkpoint / Resume 与 Run Trace，复用已提交结果续跑。修复多工具协议解析与引用交付后，同模型、同预算的 SciFact 8 题×2 配置复测中，端到端通过率 **31.25%→75.0%**，协议失败 **9/16→0/16**。

2. **可信 RAG 与原文核验：**针对论文术语检索不稳、只读摘要和结论缺乏出处，构建 **FTS5/BM25＋BGE-M3＋RRF** 混合检索，结合原文窗口续读、邻接片段补读与 Claim–Evidence–Source 绑定，支持页码追溯、逐段核验和局部修订。在 SciFact **5,183 篇摘要、20 道可评分保留题**上，相较 BM25，Recall@5 **75.0%→87.5%**，MRR@5 **0.604→0.714**。

3. **分层 Memory 与上下文治理：**针对多轮研究中历史信息难复用、上下文持续膨胀，设计会话记忆、研究区共享记忆和全局偏好，结合混合历史检索、结构化压缩与原文回查，保留任务约束、进度及证据指针。LongMemEval **25 道保留题**的历史召回 Recall@5 **8.33%→37.47%**；24 组双次压缩测试中，工具协议保持 **24/24**、精确事实读回 **22/24**。

4. **Multi-Agent 调研协作：**针对跨论文、多主题研究中的独立子问题，设计主控拆解、双路研究子 Agent 并行执行与结果归并；每路独立维护模型上下文、工具循环和证据，主控汇总报告与失败状态。基于 SQLite 实现原子委派、幂等调用、父子取消和过期回调隔离，真实单/双 worker 对照累计交付 **16 份子研究报告**。

5. **Auto Research 与 Agent-as-Tool：**针对调研完成后仍需人工转交编码、整理实验结果的问题，将 Codex CLI 工具化，由研究 LLM 按进展提出待验证假设、选择基线、制定对比/消融方案并委派实现；宿主独立运行实验、回传指标，主控据此补充调研、修订方案或结束。实现方案、配置、代码和结果版本追溯，在 SciFact、A-MEM/LoCoMo 案例中跑通有限研究与实验流程。

6. **反馈驱动策略与评测闭环：**将漏检、漏读和无依据结论等失败反馈沉淀为策略候选，通过配对评测、质量与成本门槛控制启用和回退。查询规划候选在历史控制集 **30 道可回答题**上，将 Recall@5 **64.92%→72.14%**；组织 QASPER、SciFact、HotpotQA、LongMemEval 等开源子集与项目场景共 **320 条任务**，分层评估检索、问答和工程可靠性，保留来源、轨迹、用量与失败案例。
