# ResearchAgent｜证据驱动的科研调研与 Auto Research 工作台

**核心技术：**Python、Agent Harness、Tool Calling、Multi-Agent、SQLite / FTS5、BGE-M3、Chroma、RRF、Layered Memory、Checkpoint / Resume、Codex CLI

**项目描述：**独立开发面向论文与技术研究的 Agent 工作台，支持日常问答、深度调研和按需启动的 Auto Research。围绕“资料检索—原文核验—研究设计—编码实验—结果反馈”构建可追溯的研究流程，重点解决原文漏读、引用不足、长任务上下文膨胀、执行中断和研究成果难以复用的问题。

**核心职责与贡献：**

1. **Agent Harness 架构与运行治理：**设计统一运行时，接通模型接入、意图路由、工具调用、预算控制和事件追踪；实现参数与权限校验、重复调用抑制、敏感信息脱敏及失败分级，按任务意图区分聊天、资料问答、调研和自动研究。在同模型、同预算的 SciFact 固定 8 题×2 配置复测中，协议解析与引用交付修复使端到端通过率 **31.25%→75.0%**，多工具协议失败 **9/16→0/16**。

2. **可信 RAG 与证据追溯：**以 SQLite 保存原文和来源元数据，Chroma 维护可重建向量索引，构建 **FTS5/BM25＋BGE-M3＋RRF** 混合检索链路；通过原文窗口续读、邻接片段补读和 Claim–Evidence–Source 关联，将结论绑定到页码、来源与内容哈希，结合逐段核验和局部修订减少错引。在 SciFact 的 **5,183 篇摘要、20 道可评分保留题**上，Recall@5 **75.0%→87.5%**，MRR@5 **0.604→0.714**。

3. **分层 Memory 与长上下文管理：**划分会话记忆、研究区共享记忆和全局偏好，支持独立会话、显式历史分支及按来源回查；结合结构化压缩和预算裁剪，保留用户约束、任务进度、工具调用对与证据指针。在 LongMemEval 25 道保留题上，混合历史检索相较关键词检索的 Recall@5 **8.33%→37.47%**；24 组压缩专项测试中，工具协议保持 **24/24**，精确事实读回 **22/24**。

4. **Multi-Agent 协作与任务恢复：**设计“研究主控—研究子 Agent—编码 Agent”分层协作，主控可将两个独立问题交给各自拥有模型上下文、工具循环和证据的子 Agent 并行处理，再归并报告与失败状态。基于 SQLite 实现原子委派、幂等调用、父子取消和检查点续跑，复用已提交工具结果，并以执行代次隔离过期回调；真实单/双 worker 对照完成 **16 份子研究报告**交付。

5. **Auto Research 与 Coding Agent 工具化：**将 Codex CLI 作为 Agent-as-Tool 接入，由研究 LLM 根据调研进展生成研究缺口、待验证假设、基线和对比/消融方案，按需委派代码实现；宿主独立执行与测量，将指标和失败返回主控，用于补充调研、方案修订或结束。建立方案、配置、代码与实验结果的版本追溯，在 A-MEM/LoCoMo 40 题开发案例中完成三组比较，候选证据 Recall@10 **55.09%→58.50%**。

6. **反馈驱动策略与评测闭环：**将漏检、漏读和无依据结论等反馈转为可追溯的策略候选，支持查询规划、覆盖重排及原文阅读策略，经过同模型配对评测后按质量、引用与成本门槛启用，退化时回退。历史控制集的 30 道可回答题上，查询规划候选 Recall@5 **64.92%→72.14%**；另组织 QASPER、SciFact、HotpotQA、LongMemEval 与项目场景共 **320 条混合任务**，分别评估检索、完整问答和工程合同，保存来源、Run Trace、用量及失败案例。
