## 我理解的项目目标

项目最终要成为一个按需进入 Auto Research 的研究 Agent，而不是把普通问答强行变成自动科研。

普通聊天、论文调研和资料问答时，系统应快速检索、阅读、总结和引用；研究区共享资料、Notes 和设置，区内允许多个独立会话，只有用户显式从历史消息分支时才继承该段历史。

用户明确给出复杂研究目标后，系统应完成：

```text
目标拆解
→ 检索论文/报告并读取原文
→ Claim–Evidence–Source
→ 总结方法、输入输出、数据集、代码和指标
→ 找研究缺口，提出待验证 HYPOTHESIS
→ 选择 baseline，设计对比与消融
→ 研究 LLM 按需调用 Codex
→ 宿主独立执行和测量
→ 根据真实指标继续调研、改方案、重跑或结束
→ 生成可追溯报告
```

Codex 是研究 LLM 可以调用的编码工具。项目本身的价值在证据约束、研究状态、工具编排、实验条件比较、反馈决策、恢复和可查交付；不把 Codex 的编码能力当作自研收益。

## 量化指标的口径

检索、记忆、原文核验和策略指标沿用 r27 证据，不改变历史报告；它们证明相应模块在指定数据/任务范围的行为，不能单独证明整个研究 Agent 的科研质量。尤其是 QASPER 原始报告的 Hit@5 与严格 Recall@5 已分开保留。
