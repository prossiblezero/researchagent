# V1：研究区、对话与后台研究

日期：2026-09-16。执行仓库：`D:\project\researchagent`。实现范围是工作台路线的 V1；V2–V4 仍按后续阶段推进。

## 问题

旧版 `/api/research` 把浏览器请求和一次研究运行绑定在一起，没有研究区和会话。断开页面后用户无法判断工作是否仍在进行；服务退出也不会留下“中断、可重试”的任务状态。

V1 需要保留旧的 runs/Evidence/Claim，同时为持续研究提供独立的历史、明确的任务状态和可下载报告。普通聊天不应该为了走 Agent Loop 而触发搜索。

## 解决方案

继续使用 Python 标准库、SQLite 和已同步的 ResearchAgent，没有新增 Python 依赖。修改范围超过八个文件，集中在服务入口、两个工作台模块、进度事件接线、页面、验收及部署文档。

| 能力 | 实现 |
|---|---|
| 研究区 | 新建、列表、读取、编辑、删除；保存名称、描述、下载根目录和时间 |
| 会话 | 每个研究区多个 conversation，按消息顺序持久化；选择状态保存在浏览器 |
| 意图 | 真实 LLM 根据本会话历史输出 JSON，服务端验证六种枚举及字段长度/类型 |
| 模糊研究 | 生成明确简报，保存默认假设；范围限制为 1–3 个子问题 |
| 后台任务 | SQLite 队列 + 一个工作线程，页面轮询真实阶段和最近动作 |
| 恢复 | queued/running 在服务重新启动时变为 interrupted；手动重试生成新 ID 并记录 retry_of |
| 报告 | 每次研究保存 Markdown、独立 HTML 和数据库元数据；含来源及 Claim-Evidence ID |
| 自动检索 | LLM 按问题选择学术索引、会议官网、论文集、预印本、官方文档等来源；无需手选站点 |
| 研究预算 | LLM 选择 quick/standard/deep；对应工具上限 8/16/24、上下文 16K/32K/64K，可提前完成 |
| 过程查看 | 页面内实时事件时间线，约 1.2 秒增量轮询；详情展开不被刷新折叠；保留 JSONL 下载 |
| 文件夹选择 | 本机 Windows 页面可打开系统目录选择窗口；远程或 Docker 仍填写服务器绝对路径 |
| 兼容 | 原 runs 及子表保留；旧 HTTP API 和 CLI 继续可用 |

CHAT 直接返回模型的聊天回复，不提供工具。RESEARCH 创建后台任务并返回 HTTP 202 和 `task_id`。LOCAL_QA、DOWNLOAD、BRAINSTORM、EXPERIMENT 显示“V1 尚不支持”，不会执行对应动作。模型错误、无效 JSON、未知意图不会自动退化成真实操作，也不会回退为离线假结果。

2026-09-16 连续问答修正：是否需要检索由问题的信息缺口决定，不要求“调研”口令。陌生论文、最新状态、遗漏质疑和需要新证据的追问自动创建研究任务；结果回复到原会话。稳定常识、整理上文及明确禁止联网的信息问答仍可直接聊天。quick 任务先给简短查证提示，完整计划仍保存在任务详情。同一会话可连续研究；解释会话内可见的报告不等于打开本地文件。V1 尚未实现上传文献库的检索，不能把会话历史当成完整知识库。复现与验收见 [隐式提问与连续追问](v1-conversational-routing.md)。

离线演示必须显式设置 `OFFLINE_MODE=1`。离线 Router 是固定规则，页面会标为“离线演示（固定数据）”；它仅用于工程回归，不代表真实 LLM 意图识别质量。真实模式缺少模型或搜索配置时返回可见错误。

## 工作原理

```text
页面 → 会话消息 → LLM 意图 JSON → 服务端字段验证
                                ├─ CHAT → 保存回复
                                ├─ 暂不支持 → 保存说明
                                └─ RESEARCH → SQLite queued → HTTP 202/task_id
                                                           ↓
                                   后台线程 claim_next → running
                                                           ↓
                                   ResearchAgent → Trace 事件 → 页面轮询
                                                           ↓
                                   runs + 报告文件 + reports + 完成消息
```

状态流转：`queued → running → completed / failed`；用户可将 queued/running 变为 cancelled，服务中断会变为 interrupted。所有终态保留，不会被迟到的工作线程覆盖。failed/cancelled/interrupted 可重试，新旧任务通过 `retry_of` 关联，重复点击不会为同一次失败创建多个活跃重试。

新任务由 LLM 按复杂度选择 quick/standard/deep，分别允许最多 8/16/24 次搜索或阅读、12/20/28 轮及一次最终总结，输入与输出共享的上下文额度分别为 16,384/32,768/65,536。这些是上限，证据足够时模型可以提前完成；历史任务保留原配置标识。沿用 Harness 的网络超时、重试、压缩及安全边界。一个运行加排队任务最多 16 个。达到预算时以 FINAL_ONLY 明确切换到只总结已有证据的模式。取消是协作式的：当前网络请求返回后在下一个 Trace 检查点停止，不再开始后续动作。

工作台只运行一个进程：数据库旁的操作系统文件锁阻止第二个服务把正在运行的任务误标为 interrupted。锁在进程退出时由操作系统释放，`.lock` 文件存在不表示数据库仍被占用。后台线程与浏览器连接没有生命周期依赖。

结构化路由保留最近 20 条消息，总历史最多 12,000 字符。最新消息最多 4,000 字符，保持完整；历史中保存的研究报告作为上下文数据，而不是新的系统指令。本地压缩摘要没有模型推理内容，但需要携带空的 reasoning_content 字段以兼容 DeepSeek 思考模式；不伪造推理，也不移除真实工具轮次的该字段。工作台允许一条消息正在做意图分析；此时另一条提交返回 409，已有后台研究继续执行。

数据库迁移只新增 `research_spaces`、`conversations`、`messages`、`research_jobs`、`reports` 和索引，保留旧 runs 及 Evidence 迁移。任务完成状态、report 元数据和完成消息在同一事务里提交；报告文件先以同目录临时文件完成，再原子改名。极端情况下进程在文件改名后、事务前崩溃，会留下无元数据的文件，但不会错误显示 completed。

报告写入 `DB_PATH` 所在目录的 `reports/<space_id>/<job_id>/`，路径只由服务端生成；HTML 对所有模型/来源文本转义。下载根目录在 V1 只验证、保存，不创建下载、不读取任意本地文件。删除研究区会删除其会话和任务元数据，但不会递归删除用户目录、旧 runs 或已生成的文件。研究区有活跃任务时先要求取消。

服务默认绑定 `127.0.0.1`，写入 API 检查 JSON 类型和同源请求。V1 是单用户本机服务，没有账号和权限系统；若要远程部署，应在反向代理层提供认证。Docker 内设置 `HOST=0.0.0.0`，宿主端口仍建议仅绑定回环地址。

### 对照的公开实现

- [Open Deep Research 固定提交](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/src/open_deep_research/deep_researcher.py)：2026-09-16 实际读取 `clarify_with_user` 与 `write_research_brief`，借鉴“结合历史形成结构化简报”的机制；V1 用普通函数实现，不引入其 LangGraph 编排和多 Agent 架构。
- [RAGTruth，ACL 2024 正式论文](https://aclanthology.org/2024.acl-long.585/)：官方页面已核实题名。它说明检索后生成仍需要独立的幻觉检查与评测；本阶段只继承已有引用验证，不宣称实现该论文的方法，也不把工作流通过率当作答案正确率。

### 关键 API

| 方法与路径 | 行为 |
|---|---|
| GET / POST `/api/spaces` | 研究区列表、新建 |
| GET / PATCH / DELETE `/api/spaces/{space}` | 读取、编辑、删除；DELETE 发送 `{}` |
| GET / POST `/api/spaces/{space}/conversations` | 会话列表、新建，body 为 `{"title":"会话名称"}` |
| GET / POST `/api/spaces/{space}/conversations/{conversation}/messages` | 历史、发送，body 为 `{"content":"你好"}` |
| POST 同上，`{"content":"研究 Agent 论文"}` | 默认 `search_scope=auto`；模型决定来源和研究预算；旧客户端 web/arxiv 参数仍兼容 |
| GET `/api/spaces/{space}/jobs` | 当前研究区任务 |
| GET `/api/spaces/{space}/jobs/{job}` | 详情、阶段、最近动作、摘要与报告元数据 |
| POST `/api/spaces/{space}/jobs/{job}/cancel` 或 `/retry` | 取消/新建重试，body 为 `{}` |
| GET `/api/spaces/{space}/jobs/{job}/run` 或 `/trace` | Evidence/Claim 详情、真实 JSONL |
| GET `/api/spaces/{space}/jobs/{job}/events?after=0` | 增量事件，返回 events、next_seq、status；每次最多 200 条，忽略未写完的末行 |
| POST `/api/folders/pick` | body 为 `{"initial":""}`；返回 path/cancelled；必须本机 Windows、回环绑定、回环客户端及同源 Origin |
| GET `/api/spaces/{space}/jobs/{job}/report.md` 或 `/report.html` | 下载、查看报告 |

所有这些详情和操作都同时验证所属研究区。`/api/runs` 等旧接口是单用户跨研究区的历史兼容入口，页面明确标为全部运行记录，不用于研究区内的上下文检索。

## 试一下

2026-09-16 自动研究与主题修订：直接发送问题，无需选择综合网络或 arXiv；模型安排资料来源和研究深度。页面采用浅紫蓝星空、原创矢量助手“星见”，保留 17–18px 正文、Markdown 排版和三个详情页签。运行时查看「实时过程」；「研究计划与默认假设」说明本次范围和额度。研究区设置中的「选择文件夹…」保留。

所有来源复用已配置搜索服务，并非新增各数据库专有 API。模型可使用 `site:dblp.org`、`site:aclanthology.org` 等查询，Tavily 自动接收相应 include_domains；无需预先锁定 arXiv。Google Scholar 的公开可检索页面可以用于发现，访问失败时需改查可访问来源；不能绕过登录或反爬。CCF 等级核对官方目录，不能凭索引收录认定。允许读取的 URL 仍须来自实际搜索。V1 支持摘要页/HTML，PDF 下载、解析和资料库属于 V2。

网络断开时页面显示可理解的连接提示，并自动尝试恢复；写入连接中断后不会自动重发，避免重复创建研究。服务进程本身仍需持续运行。最新验收与限制见 [自动研究修订](v1-auto-research.md)，前次体验验收保留为历史记录。

```powershell
cd D:\project\researchagent
conda activate evidence-agent
$env:OFFLINE_MODE='1'
python server.py
```

打开 `http://127.0.0.1:8000`：

1. 创建“Agent”和“RAG”两个研究区，各自建立会话。
2. 在 Agent 研究区输入“你好”，得到聊天回复，后台任务列表仍为空。
3. 输入“我想研究一下 Agent”，看到任务 ID、研究简报、默认假设及阶段变化。
4. 完成后下载 Markdown、打开 HTML、查看证据与 Trace。固定资料只演示链路，不是实时调研结果。
5. 切换 RAG 研究区，历史和任务应为空。刷新页面后仍保持所选研究区及会话。
6. 真实任务运行中关闭页面，后台继续；进程重启后，尚未完成任务显示中断并提供重试。

使用已有 `.env` 进行真实研究：

```powershell
Remove-Item Env:OFFLINE_MODE -ErrorAction SilentlyContinue
python server.py
```

如果 `.env` 自身设置了 `OFFLINE_MODE=1`，也要取消该设置。凭据始终通过环境读取，不进入报告或 Git。默认 `DB_PATH=data/evidence_agent.db`。在 Docker 中使用持久卷：

```powershell
docker build -t researchagent .
docker run --rm -p 127.0.0.1:8000:8000 --env-file .env -v research-data:/app/data -v research-traces:/app/traces researchagent
```

`.dockerignore` 排除 `.env`、运行数据和 Trace，避免把本机密钥写进镜像。
